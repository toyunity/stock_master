# 지수 선물(코스피200 주간·야간 + 나스닥) 대시보드 표시 — 설계

작성 2026-07-31 · 선행: [futures-plan.md](../../futures-plan.md)(7/19 실검증 계획), [yasun-gg-teardown.md](../../yasun-gg-teardown.md)(7/30 경쟁 서비스 소스 역추적)

사용자 결정: **범위=셋 다** · **야간 REST 불가 시 WS 폴백** · **표시=기존 지수 칩 스트립 합류** · **WS 충돌은 공유 세션 리팩터로 해소**

**갱신(2026-08-04)**: G1·G3 실측 완료, G2는 야간 무인 프로브 예약 후 미실행. 나스닥 레그는 이 스펙이
서술한 KIS 해외선물(`ffcode.mst` → `HHDFC55010000`) 경로가 **계정 레벨로 차단**되어 QQQ ETF
프록시로 피벗했다 — 아래 §검증 게이트에 상세, 해외선물 관련 서술은 취소선 없이 실측 결과로 갱신했다.
`WsSession`(§WsSession)은 G2 결과가 나올 때까지 여전히 조건부·미착수다.

## 목표

대시보드 상단 지수 칩 스트립에 선물을 시간대 적응으로 표시한다. 야간(18:00~06:00)에 다음 날
시초가를 미리 가늠하는 것이 주 목적이다.

**칩은 2개다**: `K200 칩` 하나가 세션에 따라 주간선물↔야간선물로 내용을 바꾸고(라벨도 함께 바뀐다),
`나스닥 칩`이 따로 하나다. 주간·야간을 동시에 두 칩으로 벌리지 않는다 — 한쪽은 항상 마감이라
자리만 먹는다.

비목표: 선물 차트·호가·미결제약정 패널, 옵션, 재배포(개인용 유지).

## 배경 — teardown이 바꾼 것

yasun.gg 분석으로 두 가지가 확정됐다.

1. **KRX 야간 파생시장은 18:00~익일 06:00**이다(futures-plan은 05:00으로 적혀 있었다 — 정정 완료).
   yasun의 1분봉도 18:00~05:49에만 존재하고 06:00~08:45가 공백이라 CME 연계가 아니다.
2. 야간선물 실시간을 무료로 얻는 경로는 **국내 증권사 오픈API뿐**이고, KIS에 필요한 TR이 다 있다
   (`H0MFCNT0` 야간선물 실시간체결, `FHPIF05030200` 선물 전광판). 우리는 이미 KIS 키를 쓴다.

즉 기술적 재현 가능성은 확인됐고, 남은 것은 REST로 되는지(WS를 피할 수 있는지)뿐이다.

## 아키텍처

기존 지수 라인과 같은 4계층을 그대로 따른다. 새 개념은 **세션 판정** 하나다.

```
backend/flow/futures.py     (신설 ~180줄, 순수 함수 — KIS 미접촉)
backend/flow/kis.py         (KisClient 메서드 2개 추가)
backend/api/marketdata.py   (get_futures() — 세션별 TTL 캐시)
backend/api/app.py          (/api/futures 라우트 1개)
backend/report/dashboard.py (#market 칩 스트립 확장, theme.py CSS 재사용)
backend/flow/wsbus.py       (조건부 신설 — G2가 REST 불가로 나올 때만)
```

`futures.py`를 새 파일로 두는 이유: `kis.py`가 이미 544줄이고 선물 세션 로직은 주식 체결 파서와
성격이 다르다. 섞으면 둘 다 읽기 어려워진다. 경계 기준은 "KIS를 만지는가"다 — `futures.py`는
순수 파서라 fixture만으로 전부 테스트되고, 네트워크·캐시·세션 상태는 `marketdata`가 진다.

### 세션별 표시 규칙

**나스닥 칩 열은 설계 당시(7/31) KIS 해외선물 기준으로 적은 것이다. 실측 후(§검증 게이트 G3) QQQ
ETF 프록시로 바뀌면서 아래 표의 나스닥 열은 다시 썼다** — QQQ는 현물(cash-market) ETF라 미국
정규장(한국시간 22:30~05:00)에만 실제로 움직이고, 그 밖에는 직전 종가를 그대로 들고 있다.

| KST | 세션 | K200 칩 | 나스닥 칩(QQQ, 실측 반영) | 주식 WS(NXT 포함) |
|---|---|---|---|---|
| 평일 08:45~15:45 | `day` | 주간선물 라이브 | 직전 종가 유지(미국 정규장 전) | 정상 |
| 15:45~18:00 | `gap` | 주간 종가 · "마감" | 직전 종가 유지 | NXT 애프터 진행 |
| 18:00~20:00 | `night` | 야간선물 라이브 | 직전 종가 유지(22:30 전) | **NXT 애프터 — 공존 필요** |
| 20:00~06:00 | `night` | 야간선물 라이브 | 22:30~05:00만 라이브, 그 외 직전 종가 유지 | 없음 |
| 06:00~08:45 / 주말 | `closed` | 직전 종가 · "마감" | 직전 종가 유지 — **배지 없음**(마감 아님, 아래 편차 참조) | 없음 |

TTL: 활성 세션 30초 / 비활성 300초(지수 라인 `_IDX_TTL=30`과 같은 리듬 — KIS 동시호출 상한
`_SEM=5`에 새로 얹히는 부담이 거의 없다). ~~`ffcode.mst` 12시간~~ — 해외선물 경로 폐기로 이 캐시도
폐기(§검증 게이트 G3).

신선도: 칩마다 `at`(체결시각)을 들고 다닌다. **"지연" 배지는 체결 정체가 아니라 갱신 실패 기준이다** —
TTL이 지났는데 새 응답을 못 받았을 때만 붙인다. 야간선물은 유동성이 얇아 몇 분씩 체결이 없는 게
정상이므로, 체결시각으로 배지를 달면 매일 밤 오탐이 난다. 나스닥은 CME 경로 자체가 막혀(G3) 무지연
여부를 확인할 수 없었다 — QQQ 프록시도 이 절의 기존 규칙(갱신 실패 시에만 "지연")을 그대로 쓴다.

**실측 후 발견한 편차(의도적 보류, §설계 초과 범위)**: 위 표는 나스닥 칩도 정비시간에 "마감"을 붙이는
것으로 설계했으나, 실제로는 K200 칩만 마감 배지를 받고 나스닥 칩은 항상 "지연"(갱신 실패 시)만
표시하며 마감 배지가 없다. 미국 장 시간이 한국 세션 경계와 다르므로 나스닥 칩의 "마감"이 무엇을
뜻해야 하는지는 아직 결정하지 않았다.

**K200 칩의 캐시-히트 라벨 지연(추가 편차)**: 캐시 히트 시 K200 칩의 `label`/`session`은 그 값을
처음 저장한 시점 기준으로 남는다(마감 여부만 매 요청 재계산). 06:00 야간→마감 전환 순간엔 TTL 한
창(최대 5분, 하루 1회)만큼 라벨 텍스트가 늦을 수 있다. 마감 배지 자체는 항상 정확하다.

## WsSession 리팩터 (조건부 — G2가 REST 불가일 때만 착수)

**상태(2026-08-04): 미착수, G2 대기 중.** G2는 야간 세션(18:00~06:00)이 열려야 실측 가능해 아직
실행하지 못했다. 무인 프로브(`data/g2_night_probe.py`/`data/g2_runner.sh`, 18:05 KST 대기·실행,
`data/g2_night.log` 기록)를 예약해 뒀다. 판정 규칙: 5분 간격 두 샘플에서 최상위 월물의 `acml_vol`
(누적거래량)이 변하면 REST로 야간 세션가가 오는 것 → 이 리팩터 불필요. 15:45 마감치에 고정돼
있으면 REST 불가 → 이 절 전체(WsSession) 착수. 결과가 나오기 전까지 아래 설계는 계획으로만 존재하고
코드는 없다.

### 왜 필요한가

`engine.py:292 _ws_loop`는 **FlowEngine 인스턴스마다** `websockets.connect`를 연다. KIS 제약은
**세션 수**(1키 1세션)지 구독 건수가 아니다(`design.md:142` — 세션당 상한 자료가 "20조합 vs 41건"으로
충돌, 보수적으로 ~10종목). 지금도 `/live` 두 종목을 동시에 열면 위반이고, 야간선물 WS는 거기에
세 번째 경쟁자로 들어간다. 특히 **18:00~20:00은 NXT 애프터마켓이 살아 있어**(`market_div="UN"` 기본,
`live_page`가 이미 "장후 NXT 15:30~20:00"을 다룸) 주식 WS를 야간선물에 양보시키면 기존 기능이 회귀한다.

### 설계

`backend/flow/wsbus.py`가 연결을 단독 소유한다.

```python
class WsSession:                      # 프로세스 싱글턴
    async def register(tr_id, tr_key, handler) -> None   # 참조계수 +1, 즉시 구독 프레임 전송
    async def unregister(tr_id, tr_key, handler) -> None # 참조계수 0이면 구독 해제
    # 재접속 시 살아 있는 등록을 전부 재구독
```

`FlowEngine`은 `_ws_loop`를 버리고 등록만 한다(체결 핸들러 → `state.apply_tick`, 프로그램 핸들러 →
`state.apply_program`). REST 폴백 루프와 상태 표시는 그대로 둔다. 선물은 세션이 `night`이고
대시보드 뷰어가 있을 때 `H0MFCNT0`을 등록한다. 등록 3건은 보수적 상한 안에 넉넉히 들어간다.

**이 리팩터는 동작 보존이 전부다.** 다음을 문구까지 그대로 옮긴다:
백오프 5→60초(지터 0~3초) · ping-pong 원문 에코 · 구독 거부 시 백오프 30초 이상 ·
`OPSP0011 → client.reset_approval()` · 상태 문구 `"실시간 연결 끊김 — N초 후 재접속"` ·
프로세스 재시작 직후 EOF 거부 대비 초기 백오프 5초.

## 에러 처리

칩 단위 독립 실패다. TR 실패·키 없음이면 그 칩만 빠지고 나머지 라인은 산다. 마지막 성공값을
캐시에 남겨 장외에도 직전값을 보여준다(지수 라인과 동일). `/api/futures`는 실패 시 빈 dict를
돌려주고 프론트는 해당 칩을 렌더하지 않는다 — 에러 토스트나 빈 자리 표시는 하지 않는다.

~~`ffcode.mst` 다운로드 실패는 나스닥 칩만 죽인다. 캐시가 남아 있으면 만료됐어도 계속 쓴다
(월물 코드는 만기 전까지 유효하므로 stale이 무응답보다 낫다).~~ — 해외선물 경로 폐기로 이 문단은
적용 대상이 없다(§검증 게이트 G3). 실제로 나간 나스닥 칩(`usquote.py::price_us`)의 실패 처리는
K200과 동일한 칩 단위 독립 실패·직전 성공값 캐시·"지연" 배지 규칙을 그대로 따른다(위 §에러 처리
첫 문단).
