# 지연 데이터 패널(대차·공매도·신용) 초보 가독성 개선 — 설계

날짜: 2026-07-20 · 상태: 브레인스토밍 확정(마스터 승인) · 엔진 불변 · `/live/{code}` 껍데기 개선

## 목적·결정

`/live/{code}` 화면의 세 지연 데이터 패널(🩳 대차잔고 · 🎯 공매도 일별 체결 · 💳 신용융자
잔고)을 **주식 초보가 바로 이해**하게 만든다. 마스터가 T+1/T+2 지연과 "실시간 아님"을
반복 질문한 데서 출발 — 데이터 성격상 이 셋은 **장 마감 후 집계·정산돼 며칠 늦게
확정**되는데, 화면이 그걸 초보 눈높이로 전달하지 못한다.

**마스터가 꼽은 개선 초점(4가지 전부)**:
1. **날짜 지연** — 기준일이 왜 오늘이 아니라 며칠 전인지·실시간이 아닌지 한눈에 안 보임
2. **실시간 vs 확정 구분** — 어느 게 "지금 압력"이고 어느 게 "며칠 전 확정"인지 안 갈림
3. **개념** — 대차·공매도·신용이 각각 무슨 뜻인지, 늘/줄이 무슨 의미인지 어려움
4. **가독성** — 회색 메모 설명이 길고 빽빽해 한눈에 안 들어옴

**불변 원칙**: 데이터 엔진·수집 주기(shortbal/shortsale/credit)와 산출값은 **그대로**.
표시(껍데기)만 바꾼다([[pwa-design-system]] — theme.py 단일 CSS 출처, 엔진 불변).

## 현재 상태 (backend/report/live_page.py:316–364)

`<div class="sechd">⚠️ 위험 신호 · 떨어질 연료</div>` 아래 3개 `.panel`:
- 각 패널: `<h2>`제목 + `<span class="fresh" id="{sb,ss,cr}-fresh">` 기준일 · `.grid3`(값 3개) ·
  `.sparkwrap`(20일) · `.sig`(판정, ss는 없음) · `<details class="inline">`(20일 추이표) ·
  `.meta`(빽빽한 설명).
- 재사용 가능한 기존 패턴: `.sechd`(섹션헤더) · `.fresh`(기준일 라벨) · `.sig`(판정) ·
  `<details class="panel"/"inline">`(펼침) · `<div class="sechd">💰 수급 …`·`📊 … 실시간` 등
  실시간 섹션은 이미 `· 실시간` fresh 라벨 보유.
- **결함(데이터 정확성)**: 신용융자 `.meta`(363행)에 **T+2 지연 표시가 없음** — 셋 중
  유일하게 결제(T+2) 기반인데 T+1로 오해 유발. credit.py:10 실측("실질 T+2")과 화면 불일치.

## 설계

### A. 상태 태그 시스템 — "실시간 vs 확정" 구분 (theme.py)

전 페이지가 일관되게 두 상태를 신호하도록 CSS 토큰/클래스 2종 추가:
- `.tag-live`(🟢 지금·실시간) — 초록(`--good`) 계열, 실시간 섹션 헤더에.
- `.tag-fixed`(🕐 확정·지연) — 뉴트럴/앰버(`--warn` 약하게) 계열, 지연 패널에.

작은 알약(pill) 스타일: `display:inline-flex; font-size:11px; font-weight:800;
border-radius:var(--r-pill); padding:2px 8px`. 라이트/다크는 기존 토큰(`--good`/`--good-bg`,
`--warn`/`--warn-bg`, `--text-2`)만 사용(신규 색 없음). 애니메이션 없음.

적용:
- 실시간 섹션 헤더(💰 수급 · 실시간 체결/호가/프로그램)에 `🟢 실시간` 태그.
- 아래 확정 밴드 및 3개 패널에 `🕐 확정` 태그.
→ 밴드를 물리적으로 옮기지 않고 **라벨로 두 밴드를 구분**(변경 최소·안전, 실시간 섹션 로직 불변).

### B. 확정 밴드 헤더 + "왜 늦어요?" 펼침

`⚠️ 위험 신호 · 떨어질 연료` sechd를 재구성(위험 프레이밍 유지 + 타이밍 명시):
```
🕐 확정 데이터 · 하루~이틀 전 (실시간 아님) · 떨어질 때 연료   [왜 늦어요? ▾]
```
`[왜 늦어요?]`는 `<details class="inline">` 펼침(기본 접힘), 내용(확정 카피):
> 이 숫자들은 **장 마감 뒤 집계·정산**돼서 **다음 영업일(공매도·대차)~이틀 뒤(신용융자)**에
> 확정돼요. 그래서 오늘이 아니라 **며칠 전 날짜**로 보이는 게 정상이에요. **지금 이 순간의
> 매수·매도 압력**은 위의 **실시간 수급·호가·체결**에서 보세요.

### C. 3개 패널을 초보 카드로 재구성 (가독성·개념·날짜)

각 `.panel` 헤더/본문 재배치(값·스파크·추이표·판정 로직은 유지, 표시만):

```
🩳 대차잔고                                🕐 7/17(목) 기준 · T+1
   1,853만주   ▲ 늘어남                       ← .val(큰 숫자) + .sig(판정, 크게)
   빌려간 주식(공매도 준비 물량). 늘면 매도 부담 ↑, 줄면 상환 신호.   ← 초보 1줄(항상)
   [ⓘ 자세히 ▾]                 〔대차 20일 ▁▂▃▅〕
```

1. **타이밍 알약**(`.tag-fixed`): `🕐 {M/D(요일)} 기준 · T+{n}`.
   - 날짜 = 각 모듈 반환 `asof`(대차=`get_history().asof`, 공매도/신용=data의 최신 행 날짜).
   - `n`: 대차·공매도 = **1**, 신용융자 = **2**(정적 라벨 — 지연은 데이터 성격상 고정).
   - 데이터 대기 중이면 `🕐 데이터 대기`(기존 문구 유지).
2. **큰 숫자 + 판정 한 줄**: 각 패널 **핵심 값**을 크게 위로, 나머지 grid 값은 [ⓘ 자세히] 안으로.
   - 핵심 값: 대차 = **잔고 주수**(sb-qty), 공매도 = **공매도 체결량**(ss-qty), 신용 = **잔고 주수**(cr-qty).
   - 판정(`.sig`): 대차·신용은 기존 `sb-sig`/`cr-sig`(전일 대비 ▲늘어남/▼줄어듦/—보합 + 의미)를
     크게. **공매도는 기존에 `.sig`가 없으므로 새 판정 로직을 만들지 않고**, 핵심 값 옆에
     **거래량 비중**(ss-ratio, 예: "비중 8.2% — 매도 압력 높음/보통/낮음")을 강조 표시한다.
3. **초보 1줄**(항상 노출, 평이한 말):
   - 대차잔고: "빌려간 주식(공매도 준비 물량). 늘면 매도 부담 ↑, 줄면 상환 신호."
   - 공매도: "실제로 공매도로 쏜 물량. 비중 높으면 그날 매도 압력이 셌다는 뜻."
   - 신용융자: "빚내서 산 주식. 급락하면 다음 날 아침 반대매매(강제청산) 연료 — 클수록 하락 가속."
4. **[ⓘ 자세히] 펼침**(progressive disclosure, `<details class="inline">`): 기존 `.meta`의 상세
   설명 + 보조 수치(금액≈·거래량 비중·대차잔고 대비 등) + 기존 "최근 20거래일 추이"표를
   이 안으로 통합. 기본 접힘.

### D. 신용융자 T+2 명시 (데이터 정확성 수정)

- 신용 패널 알약 = `· T+2`(대차·공매도는 `· T+1`).
- 신용 초보 1줄/자세히에 "결제 기준이라 **이틀(T+2) 늦게** 확정" 명시.

## 범위·파일

- `backend/report/live_page.py` — 마크업(316–364행 3패널 + 실시간 섹션 헤더 태그) + JS 라벨
  (fresh/알약 채우는 부분). 값·스파크·판정·추이표 계산 로직은 그대로.
- `backend/report/theme.py` — `.tag-live`/`.tag-fixed` 알약 토큰(기존 색 토큰 재사용).
- **엔진(shortbal/shortsale/credit)·API·수집 주기 변경 없음.**

## 접근성·반응형·다크

- 알약은 색 + **텍스트(🕐/🟢, T+1/T+2)** 병기 — 색만으로 구분 금지(색약 대응).
- 기존 라이트/다크 토큰만 사용(신규 하드코딩 색 0). 애니메이션 없음(`prefers-reduced-motion` 무관).
- `<details>`는 키보드 포커스·네이티브 접힘 그대로. 아이폰 폭에서 알약이 제목과 한 줄에
  안 들어가면 줄바꿈 허용(제목 아래로).

## 알려진 제약

- 알약 날짜는 각 모듈 `asof`에 의존 — 데이터 미수집(대기) 시 `🕐 데이터 대기`로 폴백.
- "실시간 vs 확정"은 **라벨링**으로 구분(섹션 물리 이동 아님) — 실시간 섹션 로직 불변 유지가
  더 안전. 추후 완전 2밴드 재배치가 필요하면 별도 작업.
