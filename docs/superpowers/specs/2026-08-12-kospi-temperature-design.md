# '코스피 온도' 그룹 — 지수 하나로 3지표 (2026-08-12)

## 왜

'지수' 섹션은 **값**을 보여준다(코스피 6,598). 그런데 초보에게 6,598은 그 자체로 아무
의미가 없다 — 최근 흐름에서 **어디쯤인지**를 모르기 때문이다. 아줌마 지수(코스피 공포탐욕)를
조사하다 나온 항목 중 비용 대비 이득이 가장 큰 것을 가져온다([[market-sentiment-candidates]]).

**새 원천이 없다.** VKOSPI에 이미 쓰는 TR(`FHPUP02120000`)을 `0001`(코스피)로 부르면
100거래일이 한 번에 온다. 나머지는 순수 계산이다.

## 마스터 결정 (기록)

- **1순위만 한다.** 아줌마 지수의 14지표 중 "코스피 일별 1콜로 나오는 3지표"만.
  수급 4종·신용스프레드·시장 breadth·백분위 표기는 이번에 안 한다.
- **칩 + 짧은 판정 단어.** 문장형 해석(`glossary.read_per` 스타일의 한 줄 문장)이 아니라,
  '지수' 섹션의 기존 칩 문법에 판정 단어를 얹는다. 빽빽하고 자리를 적게 먹는 쪽.
- 지표는 **셋 다** 유지한다(하방 변동성을 빼는 안은 기각).

## 실측 (2026-08-12, 코스피 100거래일)

```
이격도(100일 단순평균 대비)   -6.34%
EMA(12) 이격                 +2.63%
하락일 평균 하락률(최근 20일)  -4.99%   (하락일 9/20)
```

`days[-1].v == now.price` → **True**(실측). 마지막 일봉이 곧 현재가이므로 **계산 전체가
종가 리스트 하나의 순수 함수**가 된다. KIS를 모킹하지 않고 리스트만으로 테스트할 수 있다.

### ⚠️ 이 표본은 정상 구간이 아니다 — 판정 구간을 여기 맞추면 안 된다

20일 창 80개를 굴려 본 하락일 평균 하락률 분포:

```
최소 0.70  ·  25% 2.32  ·  중앙 3.69  ·  75% 4.64  ·  최대 6.00  (%p)
```

**중앙값이 3.69%p다.** 평상시 코스피 하락일은 0.6~1.0%p 수준이므로, 이 100일은 통째로
격동 구간이다(같은 창의 VKOSPI가 48.51~96.94, 중앙 73.52였던 것과 일치한다).

여기에 맞춰 구간을 잡으면 오늘의 4.99%p가 "보통"으로 읽힌다 — **[[market-sentiment-candidates]]에
기록한 백분위 창 길이 함정을 정확히 반복하는 것**이다. 그래서 구간은 **절대 수준**으로 잡고,
이 표본에 맞추지 않는다.

**구간 숫자의 근거는 약하다**(장기 표본이 없다). 한 곳(`_BANDS`)에 모아 두고 문서에
'잠정, 관찰 후 조정'으로 명시한다. 이 값들은 사실이 아니라 **현재의 판단**이다.

## 설계

### A. 칩 모양 — 신선도 줄 계약을 깨지 않는다

`.gb`(칩 세 번째 줄)은 2026-08-12에 **"이 값이 얼마나 신선한가"**로 계약을 못 박은 자리다
(`2026-08-12-index-section-design.md` C절). 거기에 판정 단어를 넣으면 한 섹션 안에서 같은
줄이 두 가지를 뜻하게 된다 — 이 저장소가 반복해서 잡아온 "주석·라벨이 조용히 틀리는" 결함과
같은 부류다.

그래서 판정은 **값 옆**(등락률이 앉던 자리)에 둔다:

```
┌────────────────────┐
│ 100일 평균          │  ← .ml   라벨
│ -6.3%    눌림       │  ← .mv   값 + 판정
│ 실시간              │  ← .gb   신선도 (다른 칩과 동일)
└────────────────────┘
```

칩 높이가 그대로 균일하게 유지된다 — 390px 실렌더로 확인한 성질을 깨지 않는다.

판정 단어는 등락률처럼 up/down 색을 쓰지 **않는다**. 이격도가 음수라고 '나쁨'이 아니기
때문이다(눌린 게 기회일 수도 있다). 무채색으로 둔다 — 색은 정보라는 theme.py 원칙에서,
여기엔 색으로 말할 방향이 없다.

### B. 그룹 위치

`국내 지수` **바로 다음**(2번째). 읽는 순서가 자연스럽다 — "코스피 6,598 (실시간)" 다음에
"그게 최근 대비 어디쯤인가".

섹션이 5그룹 12칩 → **6그룹 15칩**이 된다. 390px에서 세 줄쯤 길어진다.

**접힌 줄(digest)에는 넣지 않는다.** 이미 폭 한계에 닿아 있다(세 값이 324px, 가용 342px).
[[market-sentiment-candidates]]의 판단과 같다: 접힌 줄은 "지금 화면에 없는 값"만 담는다.

### C. 모듈 경계

```
backend/flow/kospitemp.py     — index_daily 1콜 + 순수 계산 (신규)
backend/api/app.py            — GET /api/kospi-temp (라우트)
backend/education/glossary.py — 판정 문구 (기존 read_* 옆)
backend/report/dashboard.py   — 그룹 하나 추가
```

**`worldidx`에 넣지 않는다.** 그 모듈은 해외 전용이고, 국내를 안 넣는 것이 직전 작업의
명시적 전제였다([[fdr-daily-last-bar-is-live]] 작업 참조).

**`/api/market`에도 넣지 않는다.** 그쪽은 30초 폴링이라 100거래일 조회를 얹으면 무거워진다.

**판정 문구는 `glossary.py`에 둔다.** `read_per`·`read_pbr`·`read_w52_pos`가 이미 사는 곳이고,
초보용 문구를 한 군데 모으는 것이 이 저장소의 방식이다.

### D. 계산 — 종가 리스트의 순수 함수

입력은 `parse_index_daily`의 `days`에서 뽑은 종가 리스트(오래된 순, 마지막이 현재가).

| 키 | 계산 | 단위 |
|---|---|---|
| `ma_gap` | `ma = mean(closes)`; `(cur - ma) / ma * 100` | % |
| `ema_gap` | EMA(12), `k = 2/13`, seed = `closes[0]`; `(cur - ema) / ema * 100` | % |
| `down_avg` | 최근 20 수익률 중 **음수만**의 `mean(abs(r))` | %p |

- `ma_gap`의 평균에는 **오늘 진행 중 봉이 포함된다**(가중치 1/100이라 무시할 수 있다).
- `ema_gap`도 마지막 값이 오늘을 15%쯤 포함한다(k=2/13). 자기참조지만 관례대로 둔다.
- `down_avg`는 **표준편차가 아니라 평균**이다. "하락한 날엔 평균 5.0% 빠졌어요"가 초보에게
  읽히지, 표준편차는 안 읽힌다. 이 지표를 넣는 이유가 그것이다.
- **데이터 부족은 None**: 종가 2개 미만 → 전부 None. 최근 20일에 하락일이 3개 미만 →
  `down_avg`만 None(표본이 너무 작다). None인 칩은 그리지 않는다 — 0으로 꾸미지 않는다.

### E. 판정 구간 (`_BANDS`) — 잠정

**절대 수준으로 잡는다.** 위 '이 표본은 정상 구간이 아니다' 참조.

| 지표 | 구간 → 판정 |
|---|---|
| `ma_gap` | ≤ −10 크게 눌림 / ≤ −3 눌림 / < +3 비슷 / < +10 위 / 그 이상 크게 위 |
| `ema_gap` | ≤ −5 크게 아래 / ≤ −1.5 아래 / < +1.5 비슷 / < +5 위 / 그 이상 크게 위 |
| `down_avg` | < 1.0 잔잔 / < 2.0 보통 / < 3.5 출렁임 / 그 이상 거침 |

오늘 값으로는 `눌림` / `위` / `거침`이 나온다.

`ma_gap`과 `ema_gap`의 판정 어휘를 다르게 하지 않는다 — 둘 다 "평균 대비 위치"라 같은 축이고,
어휘가 다르면 나란히 놓았을 때 비교가 안 된다. 구간 폭만 다르다(장기는 넓게, 단기는 좁게).

### F. 신선도

코스피 지수는 09:00~15:30(KRX 정규장)에만 움직인다. `dashboard.py`의 `krIndexLive()`를
그대로 쓴다 — 국내 지수 칩과 **같은 판정**이어야 한다(같은 원천의 같은 봉이다).
`pulseState`를 쓰지 않는 이유도 그쪽에 이미 적혀 있다(NXT 프리/애프터를 장중으로 친다).

### G. 응답 계약

```json
{"asof": "ISO(KST)",
 "items": [{"key": "ma_gap", "label": "100일 평균", "value": -6.34,
            "unit": "%", "verdict": "눌림"}, ...]}
```

`verdict`를 **서버가 실어 내린다.** 프런트가 임계값을 들고 있으면 판정 기준이 두 군데로
갈라진다 — `unit`·`rate_unit`·`basis_kind`를 데이터에 실은 것과 같은 이유다.

값이 None인 항목은 `items`에서 **빠진다**(null로 보내지 않는다). 전부 빠지면 `items: []`이고,
프런트는 그 그룹을 안 그린다.

**프런트 어댑터가 채우는 것**(국내 지수·지수 선물 그룹과 같은 방식 — 서버는 이 그룹의
신선도를 모른다):

- `fresh`: `krIndexLive() ? '실시간' : '마감'` → `gfresh(it)`가 그대로 쓴다(F절)
- `rate`는 **쓰지 않는다.** 이 칩엔 등락률이 없다. 값 옆의 `.mr` 자리에 `verdict`를
  **무채색으로** 넣는다(up/down 클래스를 붙이지 않는다 — A절). 즉 `gchip`이 아니라
  이 그룹 전용 렌더가 필요하거나, `gchip`이 `it.verdict`를 알아보게 한 줄을 더한다.
  후자를 택한다: 칩 문법이 하나로 유지된다.

## 실패 처리

- KIS 실패·데이터 부족 → 그룹만 빠지고 섹션의 나머지는 뜬다(섹션의 기존 원칙).
- TTL 60초(해외지수와 동일 — 마지막 봉이 장중에 움직인다). 실패 쿨다운은 기존 관례대로.
- 키 없음을 라우트에서 막지 않는다 — 예외가 그룹 생략으로 흡수된다(`/api/worldidx`와 같은 관례).

## 테스트

- **순수 계산 골든**: 손으로 만든 종가 리스트로 `ma_gap`·`ema_gap`·`down_avg`를 검산.
  경계마다 판정이 바뀌는지(구간 양끝 ±0.01), 데이터 부족 시 None인지.
- **오늘 실측값 회귀**: 2026-08-12 코스피 100거래일에서 −6.34 / +2.63 / 4.99가 나오는지
  픽스처로 고정(계산을 바꾸면 이 테스트가 먼저 빨개진다).
- **라우트**: 200 + 계약 키 집합. `verdict` 누락 0건.
- **렌더**: node 하니스로 6그룹 15칩, 판정 단어가 값 옆에 오고 `.gb`는 신선도인지.
- **390px 실렌더**: 캔 데이터 주입 경로로(`harness verify`로는 이 섹션을 못 본다 —
  `2026-08-12-index-section-design.md`에 이유가 있다). 칩 높이가 여전히 균일한지가 핵심.
- 네트워크는 `tests/conftest.py`의 오프라인 가드가 이미 막는다 — 스텁을 빼먹으면 실패한다.

## 하지 않는 것

- 백분위 표기 — 창 길이 함정 때문에 **매일 저장이 선행**이다([[market-sentiment-candidates]])
- 시장 breadth(상승/하락 종목수) — 원천 미확인
- 수급 4종(예탁금·신용융자·미수금·반대매매) — 원천이 KOFIA/KRX
- 신용스프레드 — 회사채 금리 원천 없음
- **합성 점수(공포탐욕 지수)** — 가중치가 자의적이고 검증 불가. 개별 지표는 사실 진술이지만
  합성 점수는 판단이다. "모르면 None, 추측하지 않는다"는 이 저장소 원칙과 충돌한다.
- 125일선 — 한 콜에 100거래일만 온다(실측). 100일선으로 하고 라벨도 `100일 평균`으로 정직하게.
- 접힌 줄(digest) 확장
