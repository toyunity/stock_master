# 변동성 지수(VKOSPI) 패널 — 설계

작성 2026-08-05 · 선행: [2026-08-05-kospi200-options-design.md](2026-08-05-kospi200-options-design.md)
(같은 4계층 패턴 · ATM 내재변동성과 상호 검증되는 값)

사용자 결정: **대상=시장 전체(VKOSPI)** · **위치=반도체 동향·관심종목 관리와 같은 줄의 접힌 섹션** ·
**항상 접힘, 펼칠 때 조회** · **해석은 차트가 한다**(교과서 기준선 쓰지 않음)

## 목표

대시보드에 "시장이 지금 얼마나 불안한가"를 보는 섹션 하나를 추가한다. 화면의 중심은
**최근 100거래일 추이 라인 차트**이고, 오늘 값이 그 안에서 어디인지를 눈으로 보여준다.

비목표: 실시간 갱신, VKOSPI 파생 전략, 종목별 변동성(ATR 등 — 별개 작업).

## 실측 확정 (2026-08-05)

**코드 `0503`.** KIS 지수 조회 TR은 이름 필드를 안 주므로 코드 스윕으로는 못 찾는다.
지수 마스터 `idxcode.mst`(zip, `https://new.real.download.dws.co.kr/common/master/idxcode.mst.zip`,
491행)에서 `00503 VKOSPI`를 찾았다. **마스터는 5자리, API는 4자리**라 앞 한 자리를 뗀다
(`00001 종합`→`0001`, `22001 KOSPI200`→`2001`과 같은 규칙). `00503`을 그대로 넣으면
`rt_cd=0`에 값이 0.00으로 온다 — 조용히 틀리는 경로다.

**한 번 호출로 현재값과 이력을 둘 다 받는다.**

| | |
|---|---|
| 경로 | `/uapi/domestic-stock/v1/quotations/inquire-index-daily-price` |
| TR | `FHPUP02120000` |
| 파라미터 | `FID_COND_MRKT_DIV_CODE=U` · `FID_INPUT_ISCD=0503` · `FID_INPUT_DATE_1=<오늘 YYYYMMDD>` · `FID_PERIOD_DIV_CODE=D` |
| `output1` | dict — 현재 시세 요약(20필드) |
| `output2` | **list(100)** — 일별 이력, **최신순**(첫 행이 오늘) |

쓰는 필드: `stck_bsop_date`(일자) · `bstp_nmix_prpr`(종가) · `bstp_nmix_prdy_vrss`(전일대비) ·
`bstp_nmix_prdy_ctrt`(등락률) · `prdy_vrss_sign`(부호).

**응답 컨테이너를 미리 못 박아 둔다** — 옵션 단건 시세에서 `output`이 아니라 `output1`인 걸
모르고 30분을 날린 적이 있다. 여기선 `output2`가 리스트다.

**기간은 고를 수 있는 게 아니다.** 이 TR은 한 번에 100행을 준다(요청 파라미터로 개수를 안 받는다).
그래서 차트 기간이 100거래일인 것은 설계 선택이 아니라 **응답 형태를 따른 것**이다.

**실측값(2026-08-05 19:40)**: 오늘 `78.55` · 전일대비 `-3.50`(−4.27%) ·
100일 범위 **최저 48.51 ~ 최고 96.94** · 빈 행 0.

### 두 방향의 상호 검증

- **우리 ATM IV와 맞는다.** 같은 날 옵션 수집의 ATM 내재변동성이 **80.03%**, VKOSPI가 **78.55**.
  재는 방식이 다른데(VKOSPI=보드 전체 30일 환산 / 우리 것=잔존 9일 단일 행사가) 1.5포인트 차이다.
  두 숫자가 서로를 뒷받침한다.
- **방향도 맞는다.** 코스피200이 +3.86% 오른 날 VKOSPI는 −4.27% 내렸다 — 공포지수의 역상관.

## 화면

반도체 동향·관심종목 관리와 같은 줄에 접힌 섹션(`<details class="sec">`) 하나. **`open` 없음.**

**접힌 상태** — 아무것도 조회하지 않는다. 라벨만.

```
▸ 변동성 · VKOSPI
```

**펼친 상태** — 이때 처음 조회한다.

```
78.55  ▼3.50 (−4.27%)

┌──────────────────────────────────────────┐
│ 96.9 ┤        ╭╮                          │
│      │   ╭─╮ ╱  ╲    ╭──╮         ●←오늘  │
│ 48.5 ┤ ─╯  ╲╯    ╲──╯   ╲───────╯        │
│      └──┬─────┬─────┬─────┬─────┬────────┘
│        4월   5월   6월   7월   8월        │
└──────────────────────────────────────────┘
최근 100거래일 · 지수와 반대로 움직입니다
```

- 라인 차트(Canvas — 옵션 차트와 같은 방식). 오늘 지점에 원형 마커 + 값.
- **가로축은 월이 바뀌는 지점에 눈금과 라벨**을 놓는다(`4월`·`5월`…). 양 끝 날짜만 찍으면
  "언제 튀었나"를 못 읽는다. 월 경계는 데이터의 `stck_bsop_date`에서 **월이 바뀌는 첫 행**으로
  잡는다 — 달력을 따로 계산하지 않는다. 휴장일 때문에 1일이 데이터에 없다(실측: 5월 경계가
  5/1이 아니라 **5/4**, 8월 경계는 **8/3**).

  **실측(2026-08-05, 100거래일 = 2026-03-12 ~ 08-05)**: 월 경계 **6개**(3·4·5·6·7·8월),
  390px에서 라벨 간격 **약 68px** — 10px 폰트 라벨(약 24px)이 넉넉히 들어간다.

  **다만 마지막 라벨이 오늘 마커와 부딪힌다.** 실측에서 `8월`이 idx 97인데 오늘은 idx 99다
  — 3포인트 거리다. 규칙: **오른쪽 끝 8% 안에 들어오는 월 라벨은 그린다, 대신 오늘 마커의
  값 라벨을 위로 올려 피한다**(옵션 차트에서 쓴 "가장자리에 닿으면 안쪽으로 접기"와 같은 방식).
  라벨끼리 겹치는 건 회귀 테스트로 고정한다.
- 월 경계에 세로 격자선을 옅게 깐다(`--border`). 눈이 구간을 나눠 읽게 하는 용도다.
- 세로축은 눈금 대신 **최저·최고 값만** 표기한다. 100포인트에 값 눈금까지 촘촘히 달면 390px에서
  겹친다(옵션 차트에서 이미 겪었다) — 가로축 라벨을 살리는 대신 세로는 양 끝만 둔다.
- 현재값은 `--font-num` 모노 + `tabular-nums`.

### 정직성 규칙

- **기준선을 지어내지 않는다.** 교과서는 VKOSPI 20 아래를 평온, 30 위를 공포로 읽지만
  이 시장은 오늘 78이고 100일 범위가 48~97이다. 실세계 기준을 갖다 붙이면 틀린 말을 하게 된다.
  **해석은 차트가 한다** — 오늘이 최근 100일 안에서 어디인지를 눈으로 보여주는 것까지만.
- **백분위·상태 문구(평온/경계/공포)를 내지 않는다.** 창을 우리가 골랐다는 사실을 숨기지 않으려면
  창을 명시해야 하는데, 그럴 바엔 차트가 더 정확하다. 사용자 결정("차트로 보여주는 게 좋겠어").
- 차트 밑 한 줄은 **지표의 성질**만 말한다("지수와 반대로 움직입니다") — 기준선이 아니다.
  앱 관례상 상승=빨강인데 VKOSPI는 오르면 나쁜 것이라, 이 한 줄이 없으면
  "코스피 빨강 · VKOSPI 파랑"인 날(오늘) 둘 다 좋은 소식이라는 걸 알기 어렵다.

## 아키텍처

기존 4계층 그대로. 새 파일은 하나다.

```
backend/flow/kis.py           parse_index_daily() + KisClient.index_daily()   (추가)
backend/api/marketdata.py     get_vkospi() — TTL 캐시                          (추가)
backend/api/app.py            GET /api/vkospi                                  (추가)
backend/report/vol_panel.py   섹션 CSS·마크업·라인차트 JS                      (신설)
backend/report/dashboard.py   자리표시자 3개 끼움                              (수정)
```

`vol_panel.py`를 따로 두는 기준은 `options_panel.py`와 같다 — dashboard.py가 이미 710줄이고
차트가 붙으면 100줄쯤 는다.

| 함수 | 입력 → 출력 | 책임 |
|---|---|---|
| `kis.parse_index_daily(js)` | 응답 → `{"now": {...}, "days": [{d, v}...]}` | `output1`/`output2` 파싱. 실패·빈 응답이면 None |
| `KisClient.index_daily(iscd, date)` | → 위 dict | TR·경로·파라미터 고정 |
| `marketdata.get_vkospi(now=None)` | → dict\|{} | 60초 캐시. 실패 시 직전값 유지 |

`days`는 **오래된 → 최신 순으로 뒤집어서** 내보낸다(차트가 왼쪽부터 그리므로). 응답이 최신순이라는
사실을 프론트까지 끌고 가지 않는다.

## 데이터 흐름

**지연 로딩이 핵심이다.** 섹션을 펼칠 때(`toggle` 이벤트) 처음 한 번만 조회한다. 안 펼치면
KIS 호출이 **0건**이다 — 대시보드를 열 때마다 나가는 호출을 늘리지 않는다.

**TTL 60초.** 지연 로딩이라 폭주 위험이 낮고, 접었다 폈다를 반복해도 1분에 한 번만 나간다.
장중/장외를 나누지 않는다 — 한 건짜리 호출에 세션 규칙을 새로 만들 값어치가 없고,
옵션 마감 시각(15:45)이 이 지수에도 그대로 적용되는지는 **확인하지 않았다**(추측하지 않는다).

## 에러 처리

**섹션 단위 독립 실패.** 조회가 실패하면 이 섹션만 통째로 숨고 다른 패널은 그대로 산다
(기업 체력·옵션 패널과 같은 관행). 마지막 성공값은 캐시에 남겨 재시도 사이에도 보여준다.
키가 없으면 `{}` → 섹션 숨김.

## 테스트

- `parse_index_daily`: fixture로 `output2` 100행 파싱 · **최신순을 뒤집는지** ·
  `output1` 없음/`rt_cd≠0`/빈 리스트 방어 · 숫자 아닌 값 방어.
- `get_vkospi`: TTL 히트/미스 · 실패 시 직전값 유지 · 키없음 → `{}`.
- `KisClient.index_daily`: TR·경로·파라미터 고정(회귀 방지) — 특히 **`0503`이지 `00503`이 아님**.
- 차트 렌더: `/live`·옵션에서 쓴 node 실행 패턴 그대로. 문자열 존재 확인이 아니라 실제 실행.
  라인이 그려지는지 · 데이터가 없을 때 섹션이 숨는지.
- **차트 라벨 회귀 3개**(옵션 차트에서 전부 실제로 터진 것들):
  - 모든 텍스트가 캔버스 **안**에 있는가(앵커만이 아니라 글리프 박스까지 — 상하 여백 요구).
  - **월 라벨과 오늘 마커 라벨이 안 겹치는가.** 마지막 월 경계가 오른쪽 끝에 붙는 게 정상이라
    (실측 idx 97 vs 99) 이건 예외가 아니라 기본 상황이다.
  - 다시 그려도 캔버스가 안 부푸는가(`cv.height` 대입이 `height` 속성을 덮어쓰므로 의도한 CSS
    높이는 `data-h`에서 읽는다 — 옵션 차트에서 190→570→1710으로 부푼 적 있다).
- **지연 로딩 회귀**: 펼치기 전에는 `fetch`가 안 나가야 한다. 이게 이 설계의 핵심 약속이다.

## 제약

- Python 3.9 · 시각은 KST(`backend.flow.kst`) · REST 전용(웹소켓 미접촉)
- 테스트는 KIS·네트워크 미접촉
- 8000 실서버 불가침(재기동은 `.venv/bin/python`)
- 상승=빨강 / 하락=파랑 · 개인용 유지(재배포 금지)
