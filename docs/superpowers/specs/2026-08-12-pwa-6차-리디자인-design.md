# PWA 6차 리디자인 — kospinow 모티브 설계

작성 2026-08-12. 발단은 `2026-08-12-kospinow-binance-tradfi-조사.md`의 §4 디자인 해부다.
그 문서는 "전면 교체는 얻는 것보다 잃는 게 크다"고 권고했고, **마스터가 전면 교체로 결정했다.**
이 문서는 그 결정 위에서 무엇을 어떻게 바꿀지 정한다.

## 전제 — 우리와 kospinow는 이미 같은 체계다

실측 결과다(같은 조사 문서 §4):

- 그들의 CSS 커스텀 프로퍼티 16개는 **전부 무채색**(배경·서피스·텍스트 램프)이고,
  의미색(`rise #ff4d5e` / `fall #3f82ff` / accent `#8b7cff`)은 CSS에 없고 JS 상수로만 있다.
- 우리 "관제(Instrument)" 체계(2026-07-20, 5차)도 동일하다 — 색=정보, 무채색 크롬, 모노 계기 숫자.
- 다크 배경 `#0a0c12`(우리) vs `#080b10`(그들), 라이트 `#eceef3` vs `#f0f4f8`. 거의 같은 값이다.

**따라서 이 개편의 본체는 색이 아니라 형태와 문법이다.** 팔레트를 갈아엎는 작업이 아니다.

### 그리고 — 문법도 절반은 이미 있었다

이 문서 초안을 쓴 뒤 `live_page.py`를 실제로 파싱해보니, 내가 "신설하겠다"고 적은 것들이
이미 구현돼 있었다. **네 번 연속으로 틀렸다:**

| 초안이 만들겠다던 것 | 실제 |
|---|---|
| `.pill` 틴트 필 | `live_page.py:76`에 이미 있음 |
| 접힌 줄 숫자 요약 패턴 | `live_page.py:559~574`(기업 체력)에 이미 있음 |
| 패널을 `.sec` 그룹으로 묶기 | **이미 6그룹으로 묶여 있음** (하나는 이미 기본 접힘) |
| `.hero` 히어로 카드 | `live_page.py:31`·`us_page.py:56`에 이미 있음 |

**그래서 "6차 전면 교체"의 실체는 전면 교체가 아니다.** 남는 건 토큰 톤 9개,
신설 컴포넌트 3개(`.rail`·`.card--up/down`·`.ago`), 기존 `.hero` 개조,
접힘 상태 기억, 숫자 요약 확장이다. 이 규모가 마스터가 기대한 것과 다르면
그때 다시 정한다 — 다만 **없는 문제를 만들어 풀지는 않는다.**

구현 단계에서도 같은 규율을 적용한다: **무엇을 만들기 전에 `grep -rn "<이름>" backend/report/*.py`.**

## 목표 (마스터 확정)

셋 다:
1. `/live` 30,000px 스크롤 지옥
2. 첫인상·마감도
3. 숫자 가독성 — 지금 무엇이 중요한 숫자인지 안 보인다

## 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 실행 방식 | **토큰 우선 + 단계 배포** | 6화면이 `.panel`·`.price`·`.grid3`·`.fresh`를 공유 → 토큰만 바꿔도 전부 따라온다. 가장 짧은 diff |
| 히어로 밀도 | **중간**(48px 숫자 + 근거 4행 + 상태줄, ≈300px) | kospinow 원본은 480px라 첫 화면을 카드 하나가 다 먹는다. 그들은 보여줄 게 2개뿐이라 가능했다 |
| 크롬 과감도 | **과감하게** — 반경 24px, 여백 확대 | 세로 증가는 감수한다(마스터 결정). **히어로는 위 결정대로 48px/4행을 유지하고, 넉넉해지는 건 주변 크롬(반경·패딩·카드 간격)이다** — 두 결정은 충돌하지 않는다 |
| 시맨틱 색 | **유지** (`--up #e5342f` / `--down #1f66e0`) | 그들의 `#ff4d5e`는 흰 카드 위 대비가 우리보다 낮다. 부드러움은 색값이 아니라 14% 틴트 필에서 온다 |
| 서체 | **시스템 유지** | Pretendard는 굽기당 766~791KB(실측). base64 인라인 시 굽기당 ~1MB — 차트 라이브러리 전체가 160KB인 걸 감안하면 자기완결 규칙과 양립 불가. 종목명·RSS 제목이 임의 한글이라 서브셋도 불가 |
| `/live` 접기 | **전부 기본 펼침 + localStorage 상태 기억** | 마스터 결정 |

### 서체 대체 수단

kospinow의 서체 인상은 **히어로 숫자의 sans 볼드 tabular**에서 온다(그들 레일 값은 모노다 — 혼용).
우리는 `font-family:inherit`(아이폰 SF Pro) + `font-weight:800` + `font-variant-numeric:tabular-nums`로
0바이트에 같은 효과를 낸다. 기존 `.price`(37px 모노)는 **지우지 않고** 하위 계기용으로 남긴다.

## §2 컴포넌트

### ⚠️ 먼저 — 착수 전 이름 충돌 검사를 반드시 한다

이 스펙 초안은 컴포넌트 5개를 "신설"하겠다고 썼다가, 실제로 grep해보니
**4개 중 2개가 이미 있었다.** 무엇을 만들기 전에 `grep -rn "<이름>" backend/report/*.py`를
돌린다. 이 리포는 내가 아는 것보다 이미 많이 갖추고 있다.

실측 결과(2026-08-12):

| 이름 | 상태 |
|---|---|
| `.hero` | **이미 있다** — `live_page.py:31`, `us_page.py:56`. `.hname`·`.price`(34px 모노)·`.chg`·`.sig` |
| `.pill` | **이미 있다** — `live_page.py:76`. 모노 상태 필(`--warn-bg`) |
| `.rail` | 없음 → 신설 |
| `.card--up/--down` | 없음 → 신설 |
| `.ago` | 없음 → 신설 |

### 신설 (3개)

```
.rail          라벨 좌(--text-2) / 값 우(--font-num) / 행 사이 1px --border-2
.card--up      카드 윗변 3px --up (하락은 .card--down)
.ago           상대시간 — CSS 클래스(--text-3·tabular) + JS 포맷터 `ago(ms)` 한 쌍.
               포맷터는 theme.py에 스크립트 상수로 두고 페이지들이 공유한다
               (파이썬 대응물은 만들지 않는다 — 상대시간은 렌더 시점이 아니라
                브라우저 시점 기준이어야 맞다)
```

### 승격 (1개)

`.pill`을 `live_page.py:76`에서 `theme.py`로 옮기고 `.pill.up`/`.pill.down` 변형만 더한다
(`--up-bg`/`--down-bg` 재사용 — 새 색 없음). 3화면 이상이 쓰게 되므로 단일 출처로 올린다.

### 개조 (1개) — `.hero`

신설이 아니라 **기존 `.hero`를 승격**한다. 지금 구조:

```
.htop   ← 목록 · 종목명 · 코드 · 배지 3개(mode/conn/mstate)
.price  34px 모노
.chg    텍스트
.note#walert · #today-line
```

바꿀 것 넷:

1. `.price` 34px 모노 → **48px `font-family:inherit`(SF Pro) `font-weight:800` `tabular-nums`**
2. `.chg` 텍스트 → **`.pill.up`/`.pill.down` 틴트 필**
3. **`.rail` 신설 배치** — 전일종가·시가/고/저·거래대금·체결강도 4행. 지금 이 값들이 히어로에 없다
4. 배지 3개(`mode`/`conn`/`mstate`)를 히어로 **하단 상태줄 한 줄**로 모으고 `.ago` 상대시간을 붙인다

**스파크라인은 넣지 않는다.** kospinow는 canvas로 그리지만 우리는 lightweight-charts
인스턴스가 이미 3개(`#chart`·`#pchart`·`#vchart`)다. 장식용 네 번째 인스턴스는 값에 비해 비싸다.
정 필요하면 이미 가진 가격 시리즈로 인라인 SVG `polyline` 한 줄이지, 차트 라이브러리가 아니다.

### 겸사겸사 지우는 것

`live_page.py:256`이 `theme.py:208`의 `.sec-body>.panel` 규칙을 **그대로 복제**하고 있다.
이번 작업에서 삭제한다.

### 재사용 — 새로 만들지 않는다

`details.sec` 접기(`dashboard.py`가 이미 사용) · `.pulse` 상태닷 · `.tag-live`/`.tag-fixed` ·
`ICON_SPRITE` · `.sig` 콜아웃 · `.grid3` 스탯 타일.

### `.ago` 상대시간 규칙

| 조건 | 표기 |
|---|---|
| 과거 60초 미만 | `N초 전` |
| 과거 60분 미만 | `N분 전` |
| 그 외 과거 | `HH:MM` |
| 미래 24시간 미만 | `N시간 뒤` |
| 미래 익일 | `내일` |
| 그 외 미래 | `N일 뒤` |

기존 `.fresh`(절대시각 캡션)는 **그대로 둔다.** 상대시간은 "지금 살아 있는가"를 말하고
절대시각은 "언제 기준값인가"를 말한다 — 우리 `basis_kind` 규율이 후자다. 둘은 대체재가 아니다.

## §3 `/live` 재편 (`backend/report/live_page.py`)

### 실측한 현재 구조 — 그룹화는 이미 끝나 있다

`live_page.py`를 파싱한 결과(2026-08-12):

```
265  .hero                                    ← 히어로가 이미 있다
280  SEC 「기업 체력」        (display:none, 데이터 오면 표시) — 접힌 줄에 PER·ROE·부채 요약
291  · 가격 차트                              ← 유일하게 그룹 밖에 있는 패널
324  SEC 「수급 — 누가 사고파나」  (open)  투자자별·프로그램·일별확정·기관세부·거래원
368  SEC 「위험 지표 — 공매도·빚」 (open)  대차잔고·공매도 일별·신용융자
462  SEC 「해외·거래소·체결」      (open)  거래소별 거래량·체결 규모 분포
496  SEC 「실시간 체결」           (closed) ← 이미 기본 접힘
506  SEC 「감시선·알림」           (open)
1487 · ADR 환산가 (_ADR_PANEL 상수, 해당 종목만)
```

**초안이 "4그룹으로 묶겠다"고 쓴 작업은 이미 6그룹으로 돼 있다.** 라벨도 한국어 요약 캡션까지
붙어 있고, 하나(`실시간 체결`)는 이미 기본 접힘이다. 재편할 게 없다.

### 그래서 실제로 남는 작업

| 할 일 | 상태 |
|---|---|
| 가격 차트(291)를 `.sec`로 묶기 | 유일하게 안 묶인 패널. **다만 히어로 바로 아래 첫 화면이라 그대로 두는 편이 낫다** — 접기 대상이 아니라 기본 콘텐츠로 본다 |
| 접힘 상태 `localStorage` 기억 | **없다 → 신설.** 그룹 id별로 저장·복원 |
| 접힌 summary의 핵심 숫자 요약 | 기업 체력(`fin-digest`)에만 있다 → **나머지 5그룹으로 확장.** `live_page.py:559~574`의 `dig` 배열 패턴을 그대로 쓴다 |
| 기업 체력 기본 상태 | **현상 유지(접힘).** 접힌 줄 숫자 요약이 이 패널의 설계 의도다 |
| 나머지 5그룹 기본 상태 | **현상 유지** — 이미 `실시간 체결`만 접힘이고 나머지는 펼침이라, 마스터가 정한 "전부 기본 펼침"과 이미 일치한다 |

### 불변식 — 패널을 하나도 지우지 않는다

`live_page.py`의 render()는 매 틱 `getElementById`를 **146곳** 돈다. `<details>`는 접혀도
노드가 남으므로 이 루프는 무사하다. **감싸기만 하고, 어떤 id 보유 노드도 제거하지 않는다.**

### 알려진 위험 — 접힌 컨테이너 안의 차트 (딱 하나로 좁혀졌다)

`createChart(..., {autoSize:true})`가 `clientWidth:0`인 접힌 `<details>` 안에서 생성되면
폭 0으로 굳는다. 차트 위치를 실측했다:

| 차트 | 위치 | 위험 |
|---|---|---|
| `#pchart` (315) | 가격 차트 패널 — **그룹 밖, 항상 표시** | 없음 |
| `#vchart` (319) | 〃 | 없음 |
| `#chart` (345) | **SEC「수급」(324~366) 안의 프로그램매매 패널** | **있음** |

즉 위험은 `#chart` 하나다. 지금은 「수급」이 `open`이라 안 걸리지만,
**localStorage 접힘 기억을 넣는 순간** 접힌 상태로 복원된 다음 방문에서 터진다.
`live_page.py:768`이 `pchart.clientWidth`를 직접 읽는 코드도 같은 계열이니 함께 확인한다.

→ `<details class="sec">`에 `toggle` 리스너를 달아 처음 열릴 때 1회 리사이즈한다.

**이건 문자열 검사로 절대 안 잡힌다.** `harness` verify 시나리오에
"「수급」 접힘 상태로 로드 → 펼침 → 캡처"를 추가해야 한다.
이 위험은 **localStorage 기억 기능이 만들어내는 것**이므로, 그 기능과 같은 커밋에서 막는다.

### 정직한 한계

기본 전부 펼침이면 **첫 방문 세로 길이는 줄지 않는다.** 30,000px 문제는
(1) 히어로 카드가 한 화면에 답을 주고 (2) 사용자가 접은 상태를 기억하는 것으로 푼다.
"열자마자 짧아진다"를 원하면 기본 접힘으로 되돌려야 한다.

## §4 단계 배포

단계마다 브랜치 → `main` 병합. **8000 재기동은 매 단계 마스터에게 묻는다.**

| 단계 | 내용 | 파일 | 검증 |
|---|---|---|---|
| 1 | 토큰 9개 + 컴포넌트(`.hero`·`.rail`·`.card--up/down`·`.ago`·`.pill` 승격) | `theme.py` (+`live_page.py` 중복 삭제) | `make test` · `make verify` 6화면 |
| 2 | `/live` 히어로 개조(48px·필·레일·상태줄) + localStorage 접힘 기억 + `#chart` toggle 리사이즈 + summary 숫자 요약 5그룹 확장 | `live_page.py` | verify에 「수급」 접힘→펼침 시나리오 추가 |
| 3 | 히어로·레일·상대시간 적용 | `dashboard.py` · `scanner_page.py` · `us_page.py` | `make verify` |
| 4 | 화면 정돈 | `widget_setup.py` · 인증 화면 | `make verify` |

1단계는 **화면 파일을 안 건드린다** — 그런데도 6화면 인상이 전부 바뀐다. 그게 토큰 우선을 고른 이유다.

### 검증 규율

- `make test` — pytest + node 렌더 스모크
- `make eval` — **통과해야 정상.** 판정 문구 골든이라 디자인 작업으로 깨지면
  그건 디자인이 문구를 건드렸다는 신호다. `eval-update`로 덮지 말고 원인을 찾는다
- `make verify` — 아이폰 폭 390/DSF3 라이트·다크 + 가로 오버플로 검출.
  **화면 고쳤으면 반드시 돌린다** — 미치환 `__LIB__`, 원화 전용 반올림이 달러에 적용된 두 버그는
  실렌더로만 잡혔다
- 수정은 **먼저 실패하는 테스트**를 쓰고 빨간지 확인한 뒤 최소 수정으로 통과시킨다
