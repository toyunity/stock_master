# 홈 상단 포트폴리오 한 줄 — "내 계좌가 지금 어떤가" (2026-11-02)

## 왜

손익은 종목 카드마다 따로 있고 합계는 **위젯에만** 있다(`widget_setup.py`의 `sumTotals`).
홈을 열어도 총평가·총손익·오늘 변동·어디에 몰려 있는지를 앱이 한 줄로 말하지 못한다.
위젯이 이미 하는 계산을 홈으로 옮기는 일이라 서버 변경이 없다.

## 결정 (Claude의 선택)

- **순수 프런트.** 홈 JS는 이미 `ITEMS`(`/api/watchlist`: shares·avg)와 `D.stocks`
  (close·change), 그리고 12초 `loadPrices`(국내 현재가)를 갖고 있다. 새 엔드포인트·서버 데이터 없음.
- **통화별로 따로**, 환율 합산 없음 — 위젯과 같은 규칙(`sumTotals` 주석: "통화 혼합은 합산 안 함").
  원화 줄, 달러 줄. 달러 보유가 없으면 달러 줄 없음.
- **보유 판정은 위젯과 같은 술어** `shares > 0 && avg != null`. 보유가 하나도 없으면 줄 자체를
  그리지 않는다(관심만 하는 사용자 화면에 빈 0원이 뜨면 안 된다).
- **오늘 변동**은 `change`(등락률)로 역산한다: `prev = close / (1 + change/100)`,
  `오늘 = (close − prev) × shares`. 새 데이터 0.
- **집중도**: 통화별 평가금액 중 최대 종목의 비중. 50% 초과면 `--warn` 톤(임계는 Claude의 선택 —
  보유가 소수 종목에 몰려 있으면 이 숫자가 늘 클 수 있다; 그래도 보여주는 게 목적이다).
- **금액 가리기 토글**: 줄을 탭하면 금액이 `•••`로, 비율은 남는다. `localStorage`에 기억.
  **기본은 "보임"**(검토 질문에 대한 Claude의 결정). 기본을 가림으로 두면 하네스 크롬이 매번
  새 프로필이라 `make verify`가 늘 `•••`만 찍어 긴 금액의 390px 가로 넘침을 영영 못 잡는다.
  대신 `harness/artifacts/`는 gitignore라 실값이 찍혀도 리포에 남지 않고, README 교체용
  캡처만 **탭으로 가린 뒤 찍는다** — README 주석의 스크린샷 규칙에 그 한 줄을 추가한다.
- **US "오늘 변동" 게이트**: `D.stocks`에는 `us_open`이 없다(검토에서 확인). 서버를 건드리지
  않기 위해 홈이 이미 60초마다 받는 `/api/semi` 응답의 `us_open`(`loadSemi`)을 전역에 담아
  쓴다. 아직 못 받았거나 실패하면 US 줄의 "오늘"은 숨긴다(평가·총손익은 그대로).
- **위치**: `관심종목 분석` 그룹 헤더 바로 아래, `#cards` 위. 적중률 줄
  ([[2026-11-02-verdict-ledger-design]])은 헤더 `seccap`에 들어가므로 겹치지 않는다.

## 목표 · 비목표

목표: 홈 첫 화면에서 스크롤 없이 총평가·총손익(원·%)·오늘 변동(원·%)·최대 비중이 보이고,
국내 장중엔 12초마다 같이 움직인다.

비목표: 환율 환산 합계, 일별 수익 추이 그래프, 종목별 비중 막대, 계좌 복수 분리, 실현손익.

실패 조건: 390px에서 가로 넘침 · 보유 없는 계정에 0원 줄 · 미국 종목 가격이 장외 종가인데
"오늘 변동"으로 표시(→ US는 `us_open`이 아니면 오늘 변동을 빼고 평가·손익만) ·
`loadPrices` 갱신 뒤 줄이 옛 값 유지.

## 화면 (390px)

```
관심종목 분석                          차트·뉴스·공시
┌──────────────────────────────────────────────┐
│ 총평가 12,480,000원     +1,230,000 (+10.9%)   │
│ 오늘 −184,000 (−1.5%)   최대 비중 SK하이닉스 62%│
├──────────────────────────────────────────────┤
│ $ 3,120.40              +$210.15 (+7.2%)      │
└──────────────────────────────────────────────┘
```

- 숫자는 계기 모노 폰트(`theme.py`의 기존 숫자 클래스), 손익 색은 `--up`/`--down`(상승 빨강·
  하락 파랑 — 이 앱의 관례. `--bad` 토큰은 없다), 집중도 50% 초과는 `--warn`.
- `ITEMS`에는 `currency`가 없다 — `market`(KR→KRW, US→USD)으로 유도한다. `sumTotals`는
  `price != null`도 요구하므로 가격 실패 종목은 합계에서 빠진다(위젯과 동일). 오늘 변동 %의
  분모는 전일 평가합이고 `change`가 null인 종목은 오늘 합산에서 뺀다.
- 가린 상태: `총평가 •••  +•••(+10.9%)`.
- 페이지 파일에 색을 직접 쓰지 않는다. 필요한 클래스가 없으면 `theme.py`에 추가.

## 구현 메모

- `sumTotals`는 위젯 JS(Python 문자열 안)라 import가 안 된다. **복사**하고 양쪽에 "원본은
  `widget_setup.py`, 술어 동일 유지" 주석. `tests/test_android_widget.py`가 `theme.py`와 색을
  대조하듯, 두 함수 본문이 같은지 문자열로 대조하는 테스트 한 줄을 둔다(드리프트 감지).
- 현재가 맵 `PX[code] = {close, change}`를 `D.stocks`로 초기화하고 `loadPrices`가 갱신한 뒤
  `renderPortfolio()`를 부른다. `ITEMS` 로드 완료 후에도 한 번 부른다(로드 순서 경합:
  `ITEMS`가 비어 있으면 줄 없음 → 채워지면 그림).
- US 현재가는 홈에서 폴링하지 않는다(설계상 페이지 로드 값). US 줄은 평가·총손익만, "오늘"은
  `/api/semi`의 `us_open`이 참일 때만(위 결정).

  보유 없음 → 빈 문자열, 가리기 → 금액 `•••`.
