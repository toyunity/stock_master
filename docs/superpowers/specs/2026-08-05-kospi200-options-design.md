## 목표

대시보드에 코스피200 옵션 섹션 하나를 추가한다. 화면의 중심은 **행사가별 미결제약정 분포
차트 두 개**다 — 누적(지금까지 쌓인 포지션)과 **당일 증감**(오늘 새로 걸린 자리). 옵션을
거래하기 위한 화면이 아니라, **시장이 오늘 어디에 돈을 걸었는지**를 읽기 위한 화면이다.

비목표: 주문·시뮬레이션, 그릭스 전량 노출, 야간 옵션, 만기 전략 분석, 재배포.

## 왜 초안(요약 지표 4개)을 버렸나 — 2026-08-05 실측

초안은 **풋콜비율·콜벽·풋벽·ATM 내재변동성** 네 숫자를 카드로 보여주는 설계였다.
전 종목을 실제로 긁어보니 그 중 둘이 성립하지 않았다.

**① 전광판은 보드의 일부만 준다.** `FHPIF05030100`은 행사가 **내림차순 상위 100행 고정**이다.
파라미터 12종(`FID_COND_MRKT_CLS_CODE`·`FID_COND_SCR_DIV_CODE`·만기·행사가 지정 추정값)을
스윕해도 창이 안 움직이고, 연속조회도 미지원(`ctx_area_*` 없음, `tr_cont` 빈값).
202608 만기 콜 390개 중 1350~1597.5만 오고 **콜 100행 전부 OTM·풋 100행 전부 ITM**이었다
(API가 `atm_cls_name`으로 직접 알려준다) — 창이 통째로 ATM 위.

**② 전 구간 최대 미결제는 사다리 양 끝에 앉는다.** 우회로로 전 종목을 받아 계산한 결과:

| | 값 | 지수 대비 | 전체 대비 비중 |
|---|---|---|---|
| 콜 벽(전 구간 최대) | 1,597.5 = **최고 행사가** | +53% | 콜 미결제의 16.2% |
| 풋 벽(전 구간 최대) | 625.0 = **최저 행사가** | −40% | 풋 미결제의 14.0% |

390칸 중 맨 끝 한 칸이 전체의 1/6을 갖는다. 가격은 각각 0.04원·0.44원 — 복권 같은 초저가,
청산 안 된 잔존 물량, 폭락 대비 보험이 경계에 쌓인 것이다. **"시장이 보는 저항선·지지선"으로
읽으면 안 되는 숫자**다.

**③ 범위를 정하면 살아나지만, 콜은 범위가 답을 정한다.** 같은 데이터를 범위만 바꿔 계산:

| 범위 | 콜 벽 | 풋 벽 |
|---|---|---|
| ±5% | 1,050 | **1,000** |
| ±10% | 1,100 | **1,000** |
| ±15% | 1,100 | **1,000** |
| ±20% | 1,250 | **1,000** |
| ±30% | 1,250 | **1,000** |

**풋 벽은 요지부동 1,000** — 범위와 무관하게 거기 몰려 있다는 뜻이고 믿을 수 있다.
**콜 벽은 범위 따라 움직인다** — 우리가 범위를 고르는 순간 답의 일부를 우리가 정하는 셈이다.

**④ 그리고 누적은 오늘의 신호가 아니다.** 당일 증감(`otst_stpl_qty_icdc`)을 같이 받아보니:

```
누적 1위 1,597.5  →  오늘 −224 (오히려 줄었다)
오늘 콜 최대 증가  →  1,300에 +2,214
오늘 풋 최대 증가  →    700에 +1,189
하루 합계          →  콜 +6,963 · 풋 +5,616
```

**누적 차트에서 하늘을 찌르던 양 끝 두 기둥이 증감 차트에서는 사라진다.** 누적은 과거의
잔재고, 오늘의 돈은 완전히 다른 자리로 갔다. 이것이 이번 설계의 중심을 증감으로 옮긴 이유다.

**⑤ 수급 주체(외국인·기관·개인)는 행사가별로 존재하지 않는다.** 세 군데서 확인:
KIS 국내선물옵션 API 전체 24개 TR에 투자자별 항목 없음 · HTS「투자자별 추정포지션[5161]」은
있으나 **상품 단위**(선물/콜근월/콜원월/풋근월/풋원월)로만 · 단건 시세 응답 30개 필드에도 없음.
거래소가 그 단위로 공개하지 않는다. **당일 증감이 그 자리를 대신한다** — "누가"는 못 보지만
"시장 전체가 오늘 뭘 했나"는 정확히 본다.

## 데이터 확보 방법 (실측 확정)

전광판으로는 보드 전체를 못 받으므로 **종목마스터 + 단건 시세**를 조합한다.

**1) 종목마스터** `fo_idx_code.mst`
(zip, `https://new.real.download.dws.co.kr/common/master/fo_idx_code.mst.zip`)
고정폭 cp949. `[0]`=구분(**5=콜 · 6=풋**) · `[1:10]`=단축코드 · `[10:22]`=ISIN · `[22:]`=이름.
**만기·행사가는 코드가 아니라 이름 필드에 있다** — `C 202608   625.0` 형식.
코드의 `01608`은 상품+연월 축약이라 `"202608"`로 검색하면 안 걸린다(초안 작성 시 이걸로 헤맸다).

```
정규식: ^([CP])\s+(\d{6})\s+([\d,]+\.\d+)   → (콜/풋, 만기 YYYYMM, 행사가)
```

**2) 단건 시세** `FHMIF10000000` · `/uapi/domestic-futureoption/v1/quotations/inquire-price`
· `FID_COND_MRKT_DIV_CODE=O` · `FID_INPUT_ISCD=<옵션 단축코드>`

**응답은 `output`이 아니라 `output1`이다**(+`output2`=코스피, `output3`=코스피200).
`output`만 읽으면 rt_cd=0에 빈 dict가 와서 "스로틀 걸렸나?"로 오진하기 딱 좋다(실제로 그랬다).

쓰는 필드: `acpr`(행사가) · `futs_prpr`(현재가) · `acml_vol`(거래량) ·
`hts_otst_stpl_qty`(미결제) · **`otst_stpl_qty_icdc`(당일 증감)** · `hts_ints_vltl`(내재변동성) ·
`delta_val` · `hts_rmnn_dynu`(잔존일수) · `futs_last_tr_date`(최종거래일).
`output3`에 **KOSPI200 현물**이 딸려 오므로 ATM 기준가를 별도 조회하지 않아도 된다.

**3) 만기 목록** `FHPIO056104C0` · `display-board-option-list` · `FID_COND_SCR_DIV_CODE=509`
→ `[{mtrt_yymm_code, mtrt_yymm}]` 11건. 근월물 자동 선택에 쓴다(하드코딩 금지).

### 유량 — 실측값과 반드시 지킬 상한

| | 실측 |
|---|---|
| 근월물 종목 수 | 780(202608) ~ **1,012**(202609). 만기마다 다르므로 최대 1,012로 계획한다 |
| 동시 3, 초당 6.9건 | 780건 113초, 실패 0건 |
| 동시 3, 초당 7.3건 | 780건 106초, **`EGW00201`(호출량 초과) 6건** |
| 배치 중 `/live` 영향 | KIS 실패 로그 증가 **0건** |

**개인 계정 REST 한도는 초당 10건**(법인 20건)이고 `/live`가 이미 2~4건/초를 쓴다.
→ **초당 5건 상한**(동시 2~3 + 페이싱)으로 돌리고, `EGW00201`은 지수 백오프로 재시도한다.
1,012건 기준 회차당 약 3.5분. 장중 매시 7회면 하루 최대 7,084건 · 약 24분.
**일일 총 한도는 KIS 공식 문서에 명시가 없다** — 걸리면 주기를 늘려 대응한다(치명적이지 않음).

## 아키텍처

선물 칩과 같은 4계층. 새 파일은 둘이다.

```
backend/flow/optmaster.py   (신설 — 마스터 다운로드·파싱·캐시. 코드↔만기↔행사가만 책임)
backend/flow/options.py     (신설 — 순수 파서 + 지표 계산. 네트워크·KIS 미접촉)
backend/flow/kis.py         (KisClient.option_quote()/option_expiries() 추가)
backend/api/marketdata.py   (get_options() — 배치 수집 + TTL 캐시 + 유량 제어)
backend/api/app.py          (GET /api/options)
backend/report/dashboard.py (섹션 + 차트 2개)
```

경계 기준은 선물 때와 같다 — **"KIS를 만지는가"**. `options.py`는 행 리스트 → 지표까지만
책임지는 순수 함수라 fixture만으로 전부 테스트된다.

### backend/flow/optmaster.py

| 함수 | 입력 → 출력 | 책임 |
|---|---|---|
| `load(cache_dir, force=False)` | → `[{code, side, expiry, strike}]` | zip 다운로드(캐시 있으면 재사용)·cp949 고정폭 파싱 |
| `front_month(rows, today)` | → `"YYYYMM"` | 오늘 이후 가장 가까운 만기 |
| `chain(rows, expiry)` | → `{"calls":[...], "puts":[...]}` | 만기 하나의 전 종목(행사가 오름차순) |

마스터는 **하루 1회만** 새로 받는다(종목이 하루 단위로 추가된다). 다운로드 실패 시 기존 캐시 사용.

### backend/flow/options.py (순수 함수)

| 함수 | 입력 → 출력 | 책임 |
|---|---|---|
| `parse_quote(js)` | 단건 응답 → `{price, vol, oi, oi_chg, iv, delta}\|None` | `output1` 파싱(빈 dict면 None) |
| `put_call_ratio(calls, puts)` | → `float\|None` | 풋 거래량 합 ÷ 콜 거래량 합(분모 0이면 None) |
| `wall(rows, spot, pct)` | → 행 `\|None` | **범위 안에서** 미결제 최대. 범위 필수 인자 — 기본값 없음 |
| `atm_iv(calls, puts, spot)` | → `{iv, strike, vol}\|None` | **오늘 거래된**(`vol>0`) 행사가 중 spot에 가장 가까운 행 |
| `top_changes(rows, n)` | → 행 리스트 | 당일 증감 상위 n(양수·음수 각각) |
| `histogram(rows, field)` | → `[{k, v}]` | 차트용 (행사가, 값) 배열 |

## 화면

대시보드 지수·선물 칩 줄 아래에 접힌 섹션(`<details class="sec">`) 하나.

**접힌 상태(요약 줄)** — 펼치지 않아도 쓸모가 있어야 한다.

```
코스피200 옵션   8월물 · 만기 9일    풋콜 0.75 · IV 87% · 오늘 콜 +6,963      [15:10 기준]
```

**펼친 상태** — 차트 둘이 주인공이다.

1. **오늘의 증감** (위에 둔다 — 이게 오늘의 신호다)
   가로축 = 행사가 전 구간, 중앙선 기준 **위로 콜 · 아래로 풋**, 막대 = 당일 증감.
   음수는 중앙선 반대쪽으로 뻗어 "줄었음"을 그대로 보여준다.
   현재 지수 세로선 + 지수 ±20% 밴드 음영. 콜·풋 각각 최대 증가 지점에 원형 마커 + 값.
2. **누적 미결제 분포** (아래에 둔다 — 맥락)
   같은 좌표계, 막대 = 누적 미결제. 양 끝 기둥이 그대로 보이는 게 요점이다.
3. **숫자 3개**: 풋콜 비율 · ATM 내재변동성 · **풋 벽**(콜 벽은 숫자로 내지 않는다)

렌더는 Canvas(행사가 390×2 = 막대 780개라 SVG보다 적합).
숫자는 `--font-num` 모노 + `tabular-nums`.

### 정직성 규칙 — 이 설계의 핵심

- **콜 벽은 숫자로 내지 않는다.** 범위 따라 1,050~1,250으로 흔들려 우리가 답을 정하게 된다.
  차트에서 눈으로 보게 두고, 단정하지 않는다.
- **풋 벽은 숫자로 낸다.** ±5%~±30% 어느 범위에서도 1,000으로 같았다. 다만 화면에
  **"지수 ±20% 안에서"**를 반드시 병기한다 — 범위를 우리가 골랐다는 사실을 감추지 않는다.
- **ATM 내재변동성은 오늘 거래된 행사가에서만 뽑는다.** 거래 0인 행사가는 시세가 낡아
  IV도 낡는다(실측: 거래된 행사가 80~92% vs 거래 0인 행사가 51~61%로 두 층이 지그재그).
  거래 0인 행사가로 계산하면 조용히 틀린 값이 나온다.
- **차트에 거래 없는 행사가를 별도 표시하지 않는다** — 미결제·증감은 거래 여부와 무관하게
  유효한 값이므로 그대로 그린다. 낡은 값 문제는 **가격·IV에만** 해당한다.
- 수집이 부분 실패하면(예: 1,012건 중 30건 실패) **실패 건수를 화면에 밝힌다**.
  풋콜비율은 합계 지표라 일부 누락이 값을 바꾼다.

## 데이터 흐름

**만기 선택**: 마스터에서 오늘 이후 가장 가까운 만기(근월물). 만기 당일 이후 자동으로 다음 월물.

**TTL**: 옵션 정규장(09:00~15:45) **3600초** / 그 외 **다음 개장까지**.
선물 칩의 `futures.session_of()` 주간 판정을 재사용하되 옵션 마감도 15:45로 같다.
캐시가 만료됐고 장중이면 **백그라운드로** 갱신하고, 화면은 직전값 + "집계 중"을 보여준다
(회차당 3.5분이라 요청을 붙잡고 있으면 안 된다). 대차잔고 최초 백필과 같은 패턴이다.

**신선도 배지**: `마감`은 세션이 닫혔을 때, `지연`은 TTL이 지났는데 갱신에 실패했을 때
(체결 정체 기준이 아니다 — 선물 칩에서 정한 규칙 그대로).

**저장**: `data/cache/options_<expiry>.json` — 다음 수집까지 살아 있고 서버 재기동에도 유지된다.

## 에러 처리

**섹션 단위 독립 실패.** 옵션 수집이 실패하면 이 섹션만 통째로 빠지고 지수·선물 칩은 그대로 산다.
마지막 성공값은 캐시에 남겨 장외에도 직전 보드를 보여준다. 선물 칩에서 칩 격리를 한 방향으로만
구현했다가 리뷰에서 잡힌 전례가 있으므로 **양방향 모두 테스트로 고정한다**.

**유량 초과(`EGW00201`)는 정상 경로다.** 실패 건만 지수 백오프로 재시도하고, 재시도 후에도
실패하면 그 종목을 빼고 진행하되 **실패 건수를 결과에 담는다**(위 §정직성 규칙).

## 테스트

- `optmaster.py`: fixture 고정폭 문자열로 파싱(콜/풋 구분, 만기 필터, 행사가 콤마 처리,
  깨진 행 방어). 네트워크 미접촉 — 다운로드는 monkeypatch.
- `options.py`: 풋콜비율(정상·분모 0·빈 보드), 벽(범위 밖 최대값을 안 집는지 — **이 설계의
  핵심 회귀**), ATM IV(거래 0인 행사가를 건너뛰는지), 증감 상위(양수·음수), 결측 필드 방어.
- `marketdata.get_options()`: 만기 선택, TTL 히트/미스, 부분 실패 시 실패 건수 보고,
  실패 시 직전값 유지, **섹션 실패가 다른 칩을 안 건드림**(양방향).
- 차트 렌더: `/live`에서 확립한 node 실행 테스트 패턴 그대로(문자열 존재 확인이 아니라 실제 실행).
  누적/증감 두 필드로 각각 그려지는지, 음수 막대가 반대쪽으로 뻗는지.
