# 코스피200 옵션 — 요약 지표 + 전광판 설계

작성 2026-08-05 · 선행: [2026-07-31-index-futures-design.md](2026-07-31-index-futures-design.md)(선물 칩 — 같은 4계층 패턴), [yasun-gg-teardown.md](../../yasun-gg-teardown.md)(옵션 전광판 TR·필드 매핑의 최초 근거)

사용자 결정: **요약 지표 + 펼치면 전광판** · **지표 4종(풋콜비율·콜벽·풋벽·ATM 내재변동성)** · **위치=대시보드 섹션** · **계산은 백엔드에서(접근안 A)**

## 목표

대시보드에 코스피200 옵션 섹션 하나를 추가한다. 접힌 상태에서 **해석된 숫자 네 개**를 보여주고,
펼치면 ATM 중심 전광판 표가 나온다. 옵션을 거래하기 위한 화면이 아니라, **시장이 어디를 방어선으로
보는지·심리가 어느 쪽인지**를 읽기 위한 화면이다.

비목표: 주문·시뮬레이션, 그릭스 전량 노출, 야간(EUREX 연계) 옵션, 만기 전략 분석, 재배포.

## 배경 — 실측으로 확인된 것 (2026-08-04)

KIS 국내옵션전광판 `FHPIF05030100`
(`/uapi/domestic-futureoption/v1/quotations/display-board-callput`)이 **우리 키로 그대로 동작한다.**
CME 같은 별도 사용권이 필요 없는 국내 상품이다.

```
params {FID_COND_MRKT_DIV_CODE:"O", FID_COND_SCR_DIV_CODE:"20503",
        FID_MRKT_CLS_CODE:"CO", FID_MTRT_CNT:"202608",
        FID_MRKT_CLS_CODE1:"PO", FID_COND_MRKT_CLS_CODE:""}
→ rt_cd 0 · output1 = 콜 100행 · output2 = 풋 100행 (202608·202609 둘 다 정상)
```

행별 주요 필드: `acpr`(행사가) · `optn_shrn_iscd`(종목코드, `B…`=콜/`C…`=풋) · `optn_prpr`(현재가) ·
`optn_prdy_ctrt`(등락률) · `optn_bidp`/`optn_askp`(호가) · `acml_vol`(거래량) · `tmvl_val`(시간가치) ·
`hts_ints_vltl`(내재변동성) · `atm_cls_name`(ATM/ITM/OTM 구분) · `seln_rsqn`/`shnu_rsqn`(잔량) ·
그릭스(`gama`/`vega`/`theta`/`rho`).

같은 계열 TR인 선물 전광판 응답에는 `hts_otst_stpl_qty`(미결제약정)가 실제로 들어온다(2026-08-04 실측:
164,214). 옵션 전광판에도 있을 가능성이 높지만 **아직 확인하지 않았다**(§검증 게이트 O2).

## 아키텍처

선물 칩과 같은 4계층. 새 파일은 하나다.

```
backend/flow/options.py     (신설 — 순수 파서 + 지표 계산, 네트워크·KIS 미접촉)
backend/flow/kis.py         (KisClient.option_board() 1개 추가 — FHPIF05030100)
backend/api/marketdata.py   (get_options() — 만기·ATM 선택 + TTL 캐시)
backend/api/app.py          (GET /api/options)
backend/report/dashboard.py (요약 카드 + 접힌 전광판 표)
```

경계 기준은 선물 때와 같다 — **"KIS를 만지는가"**. `options.py`는 응답 → 행 리스트 → 지표까지만
책임지고 순수 함수라 fixture만으로 전부 테스트된다. 만기 선택·ATM 기준가·캐시·실패 처리는
`marketdata`가, 표시는 `dashboard.py`가 진다.

### backend/flow/options.py (순수 함수)

| 함수 | 입력 → 출력 | 책임 |
|---|---|---|
| `parse_board(js)` | 전광판 응답 → `{"calls": [...], "puts": [...]}` | 행 파싱(행사가·가격·등락·거래량·미결제·IV) |
| `put_call_ratio(calls, puts)` | 행 리스트 → `float\|None` | 풋 거래량 합 ÷ 콜 거래량 합 |
| `wall(rows)` | 행 리스트 → 행 `\|None` | 미결제(없으면 거래량) 최대 행 = 벽 |
| `atm_row(rows, underlying)` | 행 리스트 + 기준가 → 행 `\|None` | 행사가가 기준가에 가장 가까운 행 |
| `board_window(calls, puts, underlying, n)` | → 행사가 오름차순 병합 행 | ATM ±n 행사가만 남긴 표 데이터 |

## 요약 지표 — 계산과 읽는 법

| 지표 | 계산 | 화면에 붙는 해석 |
|---|---|---|
| **풋콜 비율** | 전 행사가 풋 거래량 합 ÷ 콜 거래량 합 | >1 "방어 심리 우세" · <0.7 "낙관 우세" · 그 사이 "중립" |
| **콜 벽** | 미결제약정 최대 **콜** 행사가 | "위쪽 저항선 — 여기서 막히는 걸로 봄" |
| **풋 벽** | 미결제약정 최대 **풋** 행사가 | "아래쪽 지지선 — 여기서 받치는 걸로 봄" |
| **ATM 내재변동성** | ATM 행의 `hts_ints_vltl` | "시장이 예상하는 앞으로의 출렁임 폭" |

숫자만 보여주지 않는다 — 각 값 아래 한 줄 해석을 붙인다. 초보에게 1.32라는 숫자 자체는 의미가 없다.

**정직성 규칙** — 계산 근거가 바뀌면 이름도 바뀌거나 값을 감춘다:

- 미결제약정을 못 얻으면(§O2) 벽은 거래량 기준으로 계산하되 화면에 **"거래량 기준"**을 명시한다.
- 분모가 0이면 풋콜비율은 `None`이고 대시(`–`)로 그린다 — 0으로 나눈 값을 만들어내지 않는다.
- **풋콜비율·벽 세 지표는 보드 전체를 받았을 때만 유효하다.** O1이 안 풀려 일부 구간(예: 깊은
  외가격 100행)만 얻는다면 그 표본으로 계산한 값은 시장 전체 심리가 아니라 표본의 심리다 —
  그 경우 세 지표를 **표시하지 않는다**. "부분 데이터로 계산한 전체 지표"가 가장 위험한 형태다.
  ATM 내재변동성은 ATM 행 하나만 있으면 되므로 이 제약을 받지 않는다.

## 데이터 흐름

**만기 선택**: 거래량 최다 월물을 자동 선택한다(선물 월물 선택과 같은 원칙 — 만기 주간에 자동으로
다음 월물로 넘어간다). 하드코딩하지 않는다.

**TTL**: 옵션 정규장(09:00~15:45) 30초 / 그 외 300초. 선물 칩이 쓰는 `futures.session_of()`의
주간 판정을 재사용하되, 옵션 마감은 15:45로 선물과 같다.

**신선도 배지**: 선물 칩에서 정한 규칙을 그대로 쓴다 — `마감`은 세션이 닫혔을 때, `지연`은 TTL이
지났는데 갱신에 실패했을 때(체결 정체 기준이 아니다).

## 에러 처리

**섹션 단위 독립 실패.** 옵션 조회가 실패하면 이 섹션만 통째로 빠지고 지수·선물 칩은 그대로 산다.
마지막 성공값은 캐시에 남겨 장외에도 직전 보드를 보여준다. 선물 칩에서 칩 격리를 한 방향으로만
구현했다가 리뷰에서 잡힌 전례가 있으므로, **양방향 모두 테스트로 고정한다**.

## 게이트 실측 결과 (2026-08-05 장중, K200 현물 1,034~1,037)

O2·O3는 풀렸고, O1은 **원래 목표는 실패했지만 우회로를 찾았다.** 그런데 우회로를 파는
과정에서 이 설계의 전제를 무너뜨리는 사실 두 가지가 나왔다 — 아래 §전제 붕괴.

**O1 — 전광판으로 ATM 구간 받기: 실패.** `FID_COND_MRKT_CLS_CODE`(빈값·MKI·W·WK·M·O·
CO·PO·01·02), `FID_COND_SCR_DIV_CODE`(20501~20505·11010), 만기, 행사가 지정 추정
파라미터(`FID_INPUT_ISCD`·`FID_INPUT_PRICE_1/2`·`FID_RANK_SORT_CLS_CODE`·`FID_INPUT_CNT_1`)를
전부 스윕했으나 창이 움직이지 않았다. 연속조회도 미지원(응답에 `ctx_area_*` 없고 `tr_cont` 빈값).
전광판은 **행사가 내림차순 상위 100행 고정**이다. 202609 만기 콜은 총 506개(335.0~1597.5)인데
그중 1350.0~1597.5만 온다 — 콜 100행 전부 `OTM`, 풋 100행 전부 `ITM`(API가 `atm_cls_name`으로
직접 알려준다) → 창이 통째로 ATM 위.

**O1 우회로 — 성공.** 두 조각을 합치면 임의 행사가를 조회할 수 있다.
- 종목마스터 `fo_idx_code.mst`(zip, `new.real.download.dws.co.kr/common/master/`)에 전 종목이 있다.
  고정폭 cp949, `[0]`=구분(**5=콜·6=풋**) · `[1:10]`=단축코드 · `[10:22]`=ISIN · `[22:]`=이름.
  **만기·행사가는 코드가 아니라 이름 필드에 있다**(`C 202608   625.0`) — 코드의 `01608`은
  상품+연월 축약이라 "202608"로 검색하면 안 걸린다.
- 단건 시세 `FHMIF10000000` + `FID_COND_MRKT_DIV_CODE=O` + `FID_INPUT_ISCD=<옵션코드>`.
  **응답은 `output`이 아니라 `output1`**(+output2·output3)로 온다 — `output`만 읽으면 rt_cd=0에
  빈 dict라 "스로틀 걸렸나?"로 오진하기 딱 좋다(실제로 그렇게 30분 날렸다).
  `futs_prpr`·`acml_vol`·`hts_otst_stpl_qty`·`hts_ints_vltl`·`acpr`·`delta_val`이 다 온다.

**O2 — 미결제약정: 있다.** 전광판·단건 모두 `hts_otst_stpl_qty`가 실제 값으로 온다.

**O3 — ATM 기준가: `client.index("2001")`(K200 현물)을 쓴다.** 전광판의 `unch_prpr`은
10,146.79로 왔는데 K200(1,036.95)도 코스피(6,592.14)도 코스닥(798.16)도 아니다.
정체 불명이므로 **쓰지 않는다**.

## 전제 붕괴 — 이 설계의 지표 3개는 정직하게 낼 수 없다

**① 활동이 ATM에 몰려 있지 않다.** 근월물(202608, 8/13 만기) 실측:

| 구간 | 행사가 수 | 거래량 합 | 미결제 합 |
|---|---|---|---|
| ATM ±8행사가(1,017.5~1,055) | 16 | 238 | 3,019 |
| 전 구간 균등 표본 | 26 | 6,073 | 16,009 |

미결제 최대는 ATM이 아니라 **1,450(5,141)·1,300(4,401)·1,000(2,073)·1,150(2,056)** 같은
멀리 떨어진 라운드 행사가다. ATM 밴드는 전체의 일부에 불과하다 →
**밴드로 계산한 풋콜비율·콜벽·풋벽은 시장 심리가 아니라 표본 심리다.** §정직성 규칙에 따라
표시 대상이 아니다. 전체 보드(390~506 × 2)를 매번 조회하는 건 불가능하다.

**② 거래 없는 행사가는 가격이 낡았다.** 같은 시각 콜 1,017.5 = 45.35인데 1,020 = 65.00 —
낮은 행사가가 더 싸다. 차익거래상 불가능한 역전이고, 원인은 **거래량 0인 행사가가 예전
시세를 들고 있어서**다. IV도 같이 낡는다: 오늘 거래된 행사가는 80~92%, 거래 0인 행사가는
51~61%로 두 층이 지그재그로 섞인다. → **ATM 내재변동성도 "오늘 실제로 거래된 행사가"로
한정해야 의미가 있다**(`acml_vol > 0` 필터 필수).

**남은 것**: 4지표 중 정직하게 낼 수 있는 건 **ATM 내재변동성 하나**(거래된 행사가 한정)뿐이다.
설계를 이 사실 위에서 다시 정하기 전에는 구현에 들어가지 않는다.

## 검증 게이트 (수동 — 하네스가 KIS 키를 차단하므로)

- **O1 — ATM 구간 확보 (이번 작업의 갈림길).** 현재 100행 상한에 걸려 깊은 외가격만 온다
  (실측: 행사가 1,350~1,597, K200은 약 1,000 — ATM 미포함). `FID_COND_MRKT_CLS_CODE` 등
  파라미터를 스윕해 ATM 중심 구간을 받는 법을 찾는다(선물 G1에서 시장구분 코드를 스윕해
  `""`를 찾아낸 것과 같은 방식). **못 찾으면 전광판 표는 성립하지 않는다** — 그때는 요약 지표만
  내보낼지 사용자에게 다시 묻는다. 표를 위해 데이터를 지어내지 않는다.
- **O2 — 미결제약정 유무.** 콜벽·풋벽이 여기 달려 있다. 선물 전광판에는 `hts_otst_stpl_qty`가
  실제로 오므로 옵션에도 있을 공산이 크지만 확인 전까지는 가정하지 않는다. 없으면 거래량 기준으로
  대체하고 화면에 명시한다(위 §정직성 규칙).
- **O3 — ATM 기준가.** 응답의 `unch_prpr`이 10,158.12로 오는데 K200(약 1,000)과 맞지 않는다.
  이 필드가 무엇인지 확인하거나, 확인이 안 되면 우리가 이미 갖고 있는 **K200 선물가**를 기준으로
  삼는다(`get_futures()`의 `k200.price`).

## 테스트

- `options.py`: fixture 기반 단위 테스트 100%. 풋콜비율(정상·분모 0·빈 보드), 벽 선택(미결제 있음/없음 폴백),
  ATM 탐색(정확히 일치·사이값·경계), 윈도우 절단(양끝 부족 시), 결측 필드 방어.
- `marketdata.get_options()`: 만기 선택, TTL 히트/미스, 실패 시 직전값 유지, **섹션 실패가 다른 칩을
  건드리지 않음**(양방향).
