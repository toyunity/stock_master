1. 개요 (Overview)

본 프로젝트는 한국 주식에 대한 사전 지식이 거의 없는 1인 사용자를 위해, 다음을 자동화하는 개인용 애플리케이션이다.

  1. 시장 스캔 — 오늘 시장에서 "이슈가 되는(급등락·거래량 급증)" 종목을 자동 선별
  2. 차트·기술적 분석 — 선별/관심 종목의 가격 패턴을 지표로 분석
  3. 뉴스·공시 수집 — 종목별 이슈(뉴스/공시)를 모아 호재·악재 판단 보조
  4. 매매 신호 + 교육 — "지금 매수 관심 / 매도 고려 / 관망"을 이유·신뢰도·손절익절과 함께, 그리고 모든 전문용어를 평어로 풀어서 제시
  5. 리포트·알림 — 모바일(PWA)에서 보기 좋은 리포트와 실시간 푸시 알림

핵심 차별점은 "초보자 교육 레이어"다. 단순히 신호를 던지는 것이 아니라, 왜 그런 신호인지·각 지표가 무슨 뜻인지를 항상 함께 설명한다.

2. 목표와 비목표 (Goals / Non-Goals)

2.1 목표 (Goals)

  • 무료 공식 API만으로 한국 주식 실시간/과거 데이터·공시·뉴스를 수집한다.
  • 검증(백테스트)된 매매 신호만 "조언"으로 제시한다.
  • 모든 화면·리포트가 초보자에게 친절하다(용어 풀이 내장).
  • 모바일(아이폰)에서 앱처럼 쓸 수 있다(PWA + 웹푸시).
  • 각 기능이 독립 모듈로 분리되어 단계별·병렬 개발이 가능하다.

2.2 비목표 (Non-Goals, YAGNI)

  • ❌ 실제 주문 실행/자동매매 — 조언만 한다. 주문은 사용자가 증권사 앱에서 직접.
  • ❌ 타인에게 추천 제공/서비스화 — 자본시장법상 투자자문업 규제를 피하기 위해 개인 단독 사용으로 한정.
  • ❌ 앱스토어 네이티브 배포 — PWA로 충분. (백엔드는 동일하므로 추후 네이티브 확장 가능)
  • ❌ 초단타(틱/HFT)·옵션·선물·해외주식 — 초기 범위는 국내 현물 주식.
  • ❌ 수익 보장/예측 단언 — 확률적 보조 도구이지 예언 도구가 아니다.

법적 제약 (반드시 준수)

  1. 투자 책임 고지문을 모든 추천 화면·리포트에 노출한다(§16 문구).
  2. KRX 실시간 시세는 재배포 제한이 있다 → 앱을 공개 서비스로 노출하지 않고 개인(단일 사용자)·비공개로 유지한다. 개인 사용이므로 자연히 충족.
  3. 뉴스 본문 저작권 — 제목/요약/링크만 저장하고 원문은 출처로 딥링크한다. finance.naver.com 스크래핑은 금지(ToS/robots 위험).
  4. 데이터 출처 표기 — DART(금융감독원), KRX, TradingView Lightweight Charts 등 출처를 표기한다.

설계 원칙

  • 각 컴포넌트는 단일 책임을 가지며 명확한 인터페이스로 통신한다 → 독립 테스트·병렬 개발 가능.
  • (L) 데이터 어댑터 레이어는 선택이 아니라 load-bearing(핵심). FDR/pykrx 같은 스크래퍼는 KRX 사이트 변경 시 깨질 수 있으므로(아래 §7.3), 소스를 추상화하고 결과를 로컬 캐시에 적재해 상위 모듈이 영향을 받지 않게 한다.

6. 데이터 흐름

6.1 실시간 경로 (장중)

KIS 웹소켓 → (B)스트림허브 → (D)지표(관심종목) → (E)신호 → [발생 시] (K)알림 + PWA 실시간 갱신
  • 대상: 관심종목(~10~20개). 실시간 웹소켓 동시구독 상한 때문(아래 §7.1).

6.2 배치 경로 (주기/장마감)

(C)스캐너[KIS 순위 API or FDR EOD] → 이슈종목 → (D)지표 + (G)뉴스/공시 → (E)신호 → (I)일일 HTML 리포트 + "오늘의 추천"
  • 대상: 시장 전체에서 선별된 후보 + 관심종목. EOD/주기 스냅샷.

6.3 캐시 전략

  • FDR/pykrx 과거 데이터는 1회 수집 후 parquet/SQLite에 적재, 재사용. 라이브/고빈도 폴링에 스크래퍼를 쓰지 않는다.

7. 데이터 소스 (조사·검증 완료)

⚠️ 검증 안내

아래 수치는 2026-06-19 웹조사+적대적 검증을 거쳤다. ⚠️ 표시는 공식 페이지로 재확인이 필요한 불확실 항목.

7.1 KIS Developers API (한국투자증권) — 실시간·시세·순위

  • 무료(개인). 단, API 키 발급 전 한국투자증권 실계좌 개설이 선행 조건(본인인증). 이후 모의투자(paper) 키만으로 시세·실시간 가능.
  • 인증: App Key + App Secret → OAuth access token(REST) + approval_key(WebSocket). 토큰 ~24h 만료 → 캐시·재사용.
  • REST: 현재가/호가/체결, 일봉(inquire-daily-itemchartprice), 분봉(inquire-time-itemchartprice), 순위(등락률/거래량 Top30, 조건검색 100).
  • WebSocket: 실시간 체결가(H0STCNT0)·호가(H0STASP0)·체결통보(H0STCNI0). 엔드포인트 real :21000 / paper :31000.
  • 한도: REST 실전 20 req/sec(에러 EGW00201), 모의 더 낮음(~2~5, 직접 측정). ⚠️ 웹소켓 동시구독 상한: 체결·호가 각 1슬롯, 세션당 상한이 자료마다 "20조합" vs "41건"으로 충돌 → 보수적으로 양쪽 구독 시 ~10종목, 체결만 시 ~20종목으로 설계하고 포털에서 실측 확인.
  • 분봉 주의: 호출당 ~30건·당일 위주 → 전일/과거 분봉은 시간창 chunk로 페이징(REST 예산 소모 주의).
  • 법적: 개인·비공개 사용 OK. KRX 실시간 재배포 금지 → 공개 노출 금지.

7.2 DART OpenAPI (금융감독원) — 공시

  • 완전 무료, 일 ~20,000콜(⚠️ "per day" 문구는 2차출처, 한도 존재는 공식). 다기업 재무조회 호출당 100사 상한.
  • 파이썬 래퍼 OpenDartReader 0.3.2 → Python ≥ 3.13 필요(MIT). → 런타임을 Python 3.13로 통일(또는 DART REST 직접 호출). 공시 목록/재무/원문 제공.
  • 공시는 "고신호 뉴스 프록시"로 활용(시장영향 큰 이벤트).

7.3 과거 데이터 — FinanceDataReader + pykrx

  • 둘 다 무료·MIT·오픈소스, 상호보완:
    • FinanceDataReader(py3.9+): fdr.DataReader('005930', start, end) 장기 일봉(2000~), StockListing('KRX') 종목 유니버스+시총.
    • pykrx(py3.10+): PER/PBR/EPS 등 펀더멘털, 투자자별 수급, 일자별 시총.
  • ⚠️ 취약성(중요): KRX가 2025-12-27부터 로그인 의무화(봇 차단 목적). pykrx 1.2.8은 KRX 로그인 엔드포인트에 KRX_ID/KRX_PW 필요, FDR StockListing('KRX')는 2026-01 한 번 깨져 0.9.101로 긴급패치됨. → (L)어댑터+로컬캐시 필수, 버전 핀, 업스트림 모니터링.
  • 생존편향 주의: 백테스트 시 상장폐지 종목(KRX-DELISTING)도 포함.
  • marcap(시총 시계열)은 pip가 아니라 git clone 데이터 저장소(1995~), 필요 시 별도.

7.4 뉴스 — 2계층 + 선택 1계층

  • PRIMARY(우선): 언론사 RSS — 한경 finance/economy 피드는 라이브 확인됨(KOSPI/삼성/SK하이닉스 뉴스 반환). 매경·뉴시스 등 추가. 제목/요약/링크/시각만 저장, 원문 딥링크. 폴링 10~15분 간격.
  • DISCLOSURE: DART 공시 = 가장 안전한 합법 1차 소스(공식·무료).
  • SEARCH(선택): 네이버 검색 API(news) — Client ID/Secret, ⚠️일 ~25,000콜(2차출처). 키워드 검색·중복제거용. 스크래핑 아님.
  • ❌ finance.naver.com 직접 스크래핑 금지(robots/ToS 위험).

7.5 지표·차트 라이브러리

  • 지표: ta(MIT, 순수 파이썬, C의존성 0) — SMA/EMA/RSI/MACD/Bollinger/Stochastic/ATR/OBV. pandas-ta(원본)는 폐기됨 → 사용 금지. 더 많은 지표 필요 시 pandas-ta-classic.
  • 차트: TradingView Lightweight Charts(Apache-2.0, 무료) — 모바일 캔들+지표 오버레이 최적, 작은 번들. 의무: TradingView 출처표기 링크(attributionLogo 옵션으로 충족). 대안 ECharts(Apache-2.0).

8. 매매 전략 & 신호 로직 (초보자용 핵심)

비밀공식·수익보장이 아니다. 검증된 표준 전략을 규칙화하고 모든 신호에 "왜?"를 붙인다.

8.1 두 가지 기본 전략

  • 추세추종(Trend-following) — "오를 때 따라 사고 꺾이면 판다."
    • 매수 예: 단기 이동평균(20일)이 장기(60일)를 상향 돌파(골든크로스) + 거래량 증가.
    • 매도 예: 데드크로스, 또는 추세선 이탈.
  • 평균회귀(Mean-reversion) — "과도하게 빠지면 반등을 노린다."
    • 매수 예: RSI ≤ 30(과매도) + 지지선 근처.

8.2 신호 합성 & 출력 규격

모든 신호는 다음 구조로 산출한다:

{
  종목, 신호: 매수관심|매도고려|관망,
  신뢰도: ★1~★5 (동일 방향 지표 개수 기반),
  이유: 사람이 읽는 한국어 근거 리스트,
  리스크: { 손절가, 1차익절가, 권장비중 },
  뉴스: 관련 호재/악재 요약,
  고지: "참고용입니다"
}

8.3 ⚠️ 백테스트 게이트 (규칙)

⚠️ 규칙

백테스트로 검증되지 않은 신호는 조언 UI에 절대 노출하지 않는다.

  • (F)백테스트 엔진이 각 전략을 과거 데이터로 평가(승률·손익비·MDD 등). 통과 기준을 넘은 전략만 (E)신호생성기가 사용자에게 "조언"으로 제시.
  • 미검증 전략은 "실험(experimental)" 라벨로만, 조언 아님.

9. 초보자 교육 설계 (앱의 차별점)

  • 인라인 용어풀이(J): 화면의 모든 전문용어에 ⓘ → 1~2문장 설명(골든크로스, RSI, 거래량, 손절 등). §17 용어집을 데이터로 사용.
  • "왜 이 신호?" 패널: 각 추천의 근거를 평어로 풀어 표시.
  • 모의 매매일지: 실제 돈 없이 "샀다/팔았다" 기록 → 결과 복기(연습·학습).
  • 리스크 교육 반복: 손절의 중요성, 한 종목 몰빵 금지, 변동성 개념을 UI 곳곳에 노출.

10. 리스크 관리 모듈 (H)

  • 손절가: 진입가 기준 고정%(예: -5%) 또는 ATR 배수(변동성 비례).
  • 익절가: 1차/2차 분할(예: +8%, +15%).
  • 포지션 사이징(교육용): "한 종목 비중 ≤ N%", 계좌 대비 1회 손실 한도 개념 안내.
  • 실제 주문은 하지 않으므로 제안·교육까지만.

12. 데이터 저장소 설계

  • SQLite (stock_master.db): 종목 마스터, 관심종목, 신호 이력, 뉴스/공시 메타, 모의매매일지, 백테스트 결과.
  • parquet (data/cache/*.parquet): 종목별 일봉/분봉 OHLCV 캐시(대용량·압축).
  • (L)어댑터: get_ohlcv(code, start, end) 같은 통일 인터페이스 → 캐시 우선, 미스 시 소스 호출 후 캐시 적재. 소스 교체가 상위에 영향 없게.

13. 개발 로드맵 (수직 슬라이스 · ⫽=병렬 가능)

원칙: 수평(데이터전부→분석전부)이 아니라 수직 슬라이스. 1주차에 동작하는 얇은 한 줄기부터, 검증된 뼈대에 병렬로 얹어간다.

S0 기반 (대부분 순차) ⫽ 병렬
  • 👤(사용자) 한국투자증권 실계좌 개설 신청 → 모의투자 API 키 발급 (외부 의존, 지금 시작)
  • 프로젝트 구조 · Python 3.13 가상환경 · 의존성
  • (L)데이터 어댑터 + 캐시 골격(SQLite 스키마, parquet 캐시 인터페이스)
  • 공통 설정/로깅/시크릿 관리
S1 MVP (목표: 1주차에 실제 동작, KIS 불필요·EOD)
  • (FDR) 관심종목 5~10개 일봉 적재 → (D)ta 지표(MA/RSI/MACD) → (E)간단 신호 1개 → (I)HTML 일일 리포트 1장
✅ 완료기준: 명령 한 번에 관심종목 리포트 HTML이 생성된다.
S2 백테스트 게이트
  • (F)백테스트 엔진: S1 신호를 과거 데이터로 검증(승률/손익비/MDD)
  • "통과 신호만 조언 노출" 규칙을 (E)에 적용
✅ 완료기준: 신호마다 백테스트 성과가 리포트에 첨부된다.
S3 뉴스/이슈 레이어 ⫽ 병렬
  • ⫽ (G1) RSS 수집(한경 등) · ⫽ (G2) DART 공시 수집 · ⫽ (G3, 선택) 네이버검색
  • → 종목 매핑 · 요약 · 호재/악재 태깅 → 리포트에 뉴스 섹션 추가
✅ 완료기준: 리포트에 종목별 최신 뉴스·공시가 붙는다.
S4 시장 스캐너
  • (C) KIS 순위 API(등락률/거래량 Top30) 또는 FDR EOD로 "오늘의 이슈 종목" 자동 선별 → 후보를 S1~S3 파이프라인에 투입
✅ 완료기준: 관심종목 외에 "오늘의 추천" 후보가 자동으로 뜬다.
S5 실시간 (KIS 키 필요)
  • (B) KIS 웹소켓 허브: 관심종목(~10~20) 실시간 체결/호가
  • 실시간 신호 평가 + (K)알림 트리거
✅ 완료기준: 장중 신호 발생 시 푸시가 온다.
S6 PWA 프론트 + 교육 + 알림 ⫽ 병렬
  • ⫽ 차트 화면(Lightweight Charts) · ⫽ 추천/리포트 화면 · ⫽ (J)용어·교육 콘텐츠 · ⫽ (K)웹푸시(service worker, VAPID)
  • PWA manifest/service worker → 아이폰 홈화면 설치
✅ 완료기준: 아이폰 홈화면 아이콘으로 열어 실시간 화면·알림을 쓴다.

병렬화 요약

  • S0 내부: 사용자 계좌신청 ⫽ 코드 기반작업.
  • S3·S6 내부: 표시한 ⫽ 지점들이 독립 작업 → 병렬 에이전트 배치 가능.
  • S1·S2·S4·S5는 앞 슬라이스 산출물에 의존 → 슬라이스 간은 대체로 순차, 슬라이스 내부는 병렬.

16. 법적·윤리 고지문 (실제 노출 문구)

투자 유의 안내

본 애플리케이션이 제공하는 모든 정보·분석·신호는 참고용이며, 특정 종목의 매수·매도를 권유하지 않습니다. 모든 투자 판단과 그 결과에 대한 책임은 이용자 본인에게 있습니다. 과거 성과(백테스트)는 미래 수익을 보장하지 않습니다. 데이터는 KIS·DART·KRX·언론사 등에서 수집되며 오류·지연이 있을 수 있습니다.

체결실제로 거래가 성사된 가격·수량
